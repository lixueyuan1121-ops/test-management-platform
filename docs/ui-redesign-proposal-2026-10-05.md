# 测试管理平台 UI 改版方案

用户最终选定「清爽易用」和「深色科技」两套全平台可切换主题，覆盖登录页、导航、业务页面、弹窗和图表。实现及验证记录见 [双主题交付记录](ui-themes-delivery-2026-10-05.md)。以下保留初始三方向比较与实施边界，作为设计过程记录。

初始方案阶段交付的是设计方案和交互示意；后续实现状态以双主题交付记录为准。本方案根据 2026 年 10 月 5 日工作区源码制定。

## 当前基础与本次改进

前端使用 Vue 3、Element Plus、Pinia 和 Vue Router，已有全局主题变量、分组导航、统一页面框架、吸顶操作区、详情侧栏和多组 UI 回归脚本。已有八组导航分类适合继续沿用。

| 源码中可观察的现状 | 本次设计建议 |
| --- | --- |
| 测评任务表有任务名、描述、用例数、对话选项、状态、最近执行、耗时、评价等信息，操作列宽 268px | 将相关字段组合成视觉单元；任务名与数量放在一起，状态与进度放在一起，降低横向扫描负担。完整信息仍可阅读 |
| 用例库在同一筛选区内呈现维度、任务筛选、数量、删除、导入和下发 | 划分筛选、页面操作、已选操作三个区域；保留所有操作、权限条件和确认流程 |
| 全局主题与页面局部样式并存，主入口还动态注入输入框背景修复 | 先盘点样式优先级，再逐页迁移；避免全局覆盖导致深色输入、弹窗或表格异常 |
| WorkspacePage 已提供吸顶工具区与窄屏筛选折叠，测评页仍有独立布局 | 统一标题、间距、筛选和批量区的视觉规则；复用组件时原事件、插槽内容与绑定保持等价 |
| 导航已有权限过滤、折叠偏好和 700px 窄屏处理 | 保留现有逻辑，只调整视觉层级；不引入跨模块共享项目状态 |

以上是源码审阅结论，不是对线上页面的完整可用性评测。

## 三种视觉方向

| 方向 | 视觉与布局 | 适用场景 | 取舍 |
| --- | --- | --- | --- |
| 简洁专业 | 浅灰底、白色导航与内容区、蓝色主操作；紧凑表格；关联字段分组 | 测评任务、各类用例库、结果列表、任务分配与管理页 | 单屏信息最多，熟练用户扫描快；长文本仍需要详情区域 |
| 深色科技 | 深蓝灰底、分层面板、克制蓝色强调；任务列表与详情并列 | 作战大屏、设备看板、执行监控；也可作为全站候选方向 | 执行状态醒目；全站采用时需要逐页处理图表、表单、弹窗和富文本的配色 |
| 清爽易用 | 浅色导航、较大留白、柔和圆角；任务卡片突出名称、说明和状态 | 工作台、工具广场、新手入口、低数量任务浏览 | 阅读舒适，但大量任务的比较效率低于表格，不宜直接替代全部资产列表 |

颜色建议：专业版主色 #245CDB，工作区 #F5F7FB，正文 #172338；科技版背景 #101621，面板 #17202F，正文 #E8EEF9；清爽版主色 #3867D6，导航 #F0F4FB。状态仍使用独立的成功、警示、错误语义，同时提供文字，不依赖颜色区分。

专业版正文建议 13–14px，标题 20–24px；清爽版增加段落间距与表单留白。桌面控件建议 32–36px 高，触屏主要操作建议至少 44px。列表、状态和详情的数字统一使用等宽数字，不给普通正文套等宽字体。

## 页面方案

### 导航与工作台

保留「工作空间、对话测评、功能测试、反馈回归、性能测试、质量与发布、设备与工具、系统管理」及全部已有入口。活动页具有清楚的选中背景，分组标题与页面标题分层。功能搜索、菜单折叠、路由高亮、个人菜单及角色展示继续使用现有实现。

工作台优先展示已有待处理事项与当前任务入口，统计卡只使用当前接口已有指标。项目选择器仍处于原页面作用域；统一外观不意味着统一项目状态，避免切换项目影响其他模块。成员与访客看到的导航仍由原权限计算决定。

### 列表与批量操作

每页按标题与项目选择、页面主操作、筛选区、列表区排列。常用筛选保持直接可见；窄屏继续采用现有折叠方式。下发、批量删除等依赖选择的操作与已选数量处于同一区域，按钮禁用、加载和确认条件完全沿用。

测评任务的「任务名、用例数、定时信息」可组合展示；「状态、最近执行数量」组合展示。执行数、通过数、判定状态和综合评价状态保持独立。算力豆缺失继续显示未获取或破折号，不显示为 0。

描述、完整批次标识、对话选项、附件及资源覆盖率仍可查看。若将原独立列移入详情，须先列出字段映射，保留原本存在的排序、筛选、复制、导出和操作能力；无法证明等价的列保持原样。示意中的列合并是候选排版，不是已确认的数据删减方案。

### 详情与报告

保留「执行结果 / 综合评价」现有标签及其按钮可见规则。长提问、预期、步骤、附件和证据使用阅读区域；顶部给出任务身份与状态，正文保持可复制、可滚动。执行配置继续使用现有表单，不把已有配置项删减成一键执行。

原型中的任务详情为阅读布局示意；原平台已有的批次切换、判定、失败重跑、导出等功能，落地时需要完整保留。本次示意没有复刻所有复杂表单，不应作为功能验收依据。

### 表单与反馈

只调整标签、间距、分区、帮助文字位置和按钮布局。保留校验、默认值、保存时机、关闭限制、失败后的输入保留及防重复提交行为。停止和删除继续走原确认，停止含义仍是未执行的不再下发、执行中的结果作废，并关闭定时。

继续区分未加载、加载中、无数据、筛选无结果、失败与部分数据等状态。已有轮询失败后的历史数据、时间戳、重试和请求隔离行为不得因布局调整丢失。

## 功能保留要求

「不影响功能」是实施验收条件，不能仅凭视觉稿承诺。每批改动需要逐项验证以下不变项。

| 范围 | 不变项 | 验证方式 |
| --- | --- | --- |
| 路由与权限 | URL、深链接、登录态、角色可见性、自动化工具权限、导航搜索结果范围 | 管理员、成员、访客及自动化工具授权组合回归 |
| 请求契约 | HTTP 方法、路径、请求体、项目与任务 ID、上传和导出参数 | 同一输入下比较改造前后的请求记录 |
| 任务执行 | 执行次数、执行机、目标设备、配置矩阵、A/B 对比、一条龙、定时、停止语义 | 执行配置与停止专项回归；取消不下发，单次确认不重复发送 |
| 选择与表单 | 默认值、校验、跨筛选选择、项目切换后的清理、失败保留输入 | 原流程断言保留，覆盖连续操作和失败恢复 |
| 结果与统计 | 状态枚举、通过率分母、耗时与成本口径、缺失值、摘要生命周期 | 固定数据比较展示值；缺失不冒充成功或零值 |
| 异步行为 | 轮询周期、取消、卸载清理、迟到响应处理 | 异常与快速切换场景回归 |
| 自动化兼容 | 用户可访问名称、已有 data-testid、重要选择器和键盘操作 | 同步检查现有 UI 脚本及录制器依赖，不能以放松业务断言换取通过 |

首批不更换 UI 框架，不升级依赖，不修改 API 封装、鉴权 store、路由表、后端、runner 或调度逻辑。若视觉要求确实需要改变行为，应作为独立需求讨论，不能混入纯 UI 改版。

## 分批落地与验收

1. 固化当前业务基线：记录本地已有未提交修改，确定实施时源码与接口基线，保存典型页面截图和关键请求样本。
2. 确定方向后制作正式样板：先改导航外观、WorkspacePage 和测评任务、用例库、结果详情三类代表页面。样式作用于明确范围，验证后再扩展主题变量。
3. 复用规则扩展：功能测试、反馈回归、性能测试按模块推进；设备与质量看板单独验证图表，系统管理页补角色与危险操作检查。
4. 按批回归并记录差异：逐项检查功能入口、字段可读性、请求参数与状态值。出现行为差异时修复或撤回该批视觉改动。
5. 发布前验收：覆盖 1440px、1280px、1024px 和 390px 视口，补 320px 边界与 200% 缩放、长中文、长标识符、空值、加载与失败状态。桌面主页面无意外横向溢出；宽表仅在自身区域滚动；操作不被吸顶区域遮挡。

优先复用的脚本包括 navigation-responsive-ui、eval-workspace-ui、eval-results-ui、eval-dispatch-stop-ui、eval-import-attachments-ui、eval-dialog-matrix-ui、admin-permissions-ui、automation-tools-permissions-ui 与 device-errors-ui。最终按实际修改范围补充功能、反馈、性能和管理模块现有回归，不能把历史“26 组通过”当成本轮通过。

文字对比度以普通文本至少 4.5:1 为目标；桌面交互目标按至少 24×24 CSS 像素或符合间距例外检查，触屏主要操作采用更大的设计目标。依据：[W3C 文字对比度](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html)、[W3C 目标尺寸](https://www.w3.org/TR/WCAG22/#target-size-minimum)。同时保留可见焦点和文本状态标签。

## 本次交付及限制

交互示意提供三种视觉方向、同一组五条虚构任务、搜索、状态筛选和详情阅读。执行、停止、编辑、新建、定时和删除展示入口及功能保留说明，不连接业务接口。导航为排版示意，不包含真实路由跳转。

初始方案阶段没有更改应用源码，也没有对线上系统做功能验证。下述示意的布局与交互检查仅用于选型；本轮实现的验证结果另见交付记录。

本地预览检查已通过：三种方向的搜索、无匹配状态、任务状态筛选、详情及综合评价标签均可操作；1024px、390px 和 320px 宽度下无页面级横向溢出，宽表在自身容器内滚动；没有未捕获的页面脚本异常。已查看三套桌面截图及深色窄屏截图。检查仅覆盖示意文件。
