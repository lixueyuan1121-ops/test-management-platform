# 反馈测试模块 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增与「功能测试」「对话测评」同级的「反馈测试」模块:机器人推送 md/zip → 结构化解析成可执行用例 → AI 补 script → 组回归集 → 定时/手动回归/勾选执行,复用 qalab-runner 通道。

**Architecture:** 完全独立建表(feedback_ 前缀 5 表),exec_run 零改动(专用项目 project_id 天然隔离 + batch_id 聚合 + payload.feedback_case_id 软关联),三触发源共用下发内核,APScheduler 内置调度。

**Tech Stack:** FastAPI + SQLAlchemy2.0 + SQLite/MySQL5.6;APScheduler(新增);前端 Vue3 + ElementPlus。补 script 复用现有 generators 引擎;下发复用 exec_run + runner 契约。

**Spec:** `docs/superpowers/specs/2026-08-24-反馈测试模块-design.md`

## Global Constraints

- 统一信封 `{code,msg,data}` + `ok()`;每 router 手写 `_to_out(obj)->dict`(枚举 `.value`、日期 `isoformat`)。
- **不用原生 JSON 列**:结构化数据 Text 存 JSON 字符串(兼容 MySQL5.6)。
- **两份 schema 同步**:`models/feedback.py` + `sql/schema.sql`。
- 全新表 `create_all` 自动建(**不**进 main.py 的 `_SKIP_TABLES`);**exec_run 零改动,无 migrate**。
- RBAC:ingest 走 `X-Bot-Token`(仿 RUNNER_TOKEN);人工接口 `get_current_user` + `assert_project_role`(专用项目 admin/member)。
- **本仓库无测试框架**:验证用一次性 Python 脚本(标注临时、用后删)+ 真实参考 md/zip 打端到端;解析器纯函数脱机验。后端命令在 `backend/` 下、SQLite。
- runner 契约不变(payload/verdict/report 同 exec_queue)。
- **提交时机听用户**:下方 commit 步骤为建议锚点,执行时若用户未要求提交则跳过。
- 参考 md 真实样本目录:`C:\Users\nanliru\Downloads\全部测试用例合集_20260824`(29 个 md)。

### Task 2: md 结构化解析器(纯函数)

独立于 DB,可脱机验证。是整个模块的解析核心。

**Files:**
- Create: `backend/app/services/feedback_parser.py`
- Verify(临时,删): `backend/_verify_parser.py`

**Interfaces:**
- Produces:
  - `parse_md(text: str) -> dict`,返回 `{req_title, req_url, feedback_summary, cases: list[dict]}`,
    每个 case: `{point_code, point_title, case_no, title, precondition, steps, expected, category, priority, auto_feasible, auto_reason, exec_kind}`。
  - `iter_zip(data: bytes) -> list[tuple[str,str]]`,返回 `[(filename, md_text), ...]`(仅 .md;utf-8 解码,容错 gbk 回退)。

- [ ] **Step 1: 写解析器**。规则:
  - 一级标题 `# 测试用例 · <名> · ...` → `req_title`(取 `·` 分段第 2 段,strip)。
  - `需求链接:<url>` 正则 → `req_url`。
  - 「反馈概述」段(`##` 或 `###` 开头,容错)整段文本 → `feedback_summary`。
  - `### 测试点 P-xxx <名>` → 当前 `point_code`(正则 `P-\d+`)+ `point_title`。
  - 表格行:按 `|` 切 12 列,跳过表头行(含「用例编号」)和分隔行(含 `---`);
    列序:`case_no, priority, _本期状态, title, precondition, steps, expected, _后续变更, category, 自动化列, _自动化状态, _状态`。
  - 「自动化列」形如 `yes / high / 理由` → 按 `/` 切:`auto_feasible=yes`(取小写首段,归一到 yes/partial/no)、`auto_reason=理由段`。
  - `exec_kind`:`auto_feasible=="no"` → `"manual"`,否则 `"gui"`。
  - steps 里 `<br>` → `\n`。
  - 容错:无表格的 md → cases 为 [](不抛异常);字段缺失给 None。

- [ ] **Step 2: 脱机验证**。写 `_verify_parser.py`:遍历参考目录 29 个 md,`parse_md` 后打印
  `文件名 → req_title / 用例数 / 首条 title+auto_feasible`,并断言总用例数 > 0、每条 title 非空。
Run: `cd backend && .venv/Scripts/python.exe _verify_parser.py`
