# 异步实测导入（2026-09-22）

## 用户流程

技能真实执行测试后 POST /api/verified-imports/jobs；接收阶段只做鉴权、设备归属及实测包结构校验，保存原始包与逐条任务后返回 HTTP 202。收到 accepted/job_id 后结束当前 Codex 任务，无 preview、全库检索、逐条结果读回或后台轮询。
功能测试 → 导入任务：每页20条，手动刷新。项目成员可查看；项目管理员处理疑似重复与失败重试。每条独立处理，其他待确认条目不阻塞已能判定的用例。

## 持久化及并发

新增 verified_import_job / verified_import_item 两表。项目/用户/external_id 唯一约束保证重传相同包复用任务，不同包409；LONGTEXT支持完整批次证据，兼容MySQL5.6。暂存任务项目ID由API验证，不设项目外键，避免提交INSERT的外键共享锁等待后台项目写锁。
后台启动后从库读取pending条目，不依赖请求进程内的临时后台任务。项目锁+条目锁定当前读串行保护判重，与旧同步导入互斥。条目状态、用例、执行记录和回执一个事务提交；事务中断自动回滚回pending，无永久running僵尸。
数据库临时错误最多尝试3次；其他处理错误保留为failed。管理员手动重试仅允许failed。后台处理与权限复核均使用真实提交者，确认管理员另行记录。确认令牌绑定候选版本，后台发现版本变化重新待确认。
新增用例不自动标记回归，统一关联同项目的“codex导入用例”需求；该需求在项目锁内查找或创建，原始需求仍保存在任务及执行快照中。复用保留原用例需求关联/回归标记/正文/脚本/评审状态，执行记录保存本次提交快照、报告、真实提交者、设备、导入任务与确认人。

先发布后端及前端构建，再重启后端；现有init_db/create_all自动创建新表。进程启动自动启动导入消费者，无需新Redis或独立调度服务。部署前备份数据库，并按现有发布流程生成 frontend/dist。

## 边界

本次将既有保守判重移到持久化后台，不宣称解决任意自然语言的语义唯一性。明确重复复用，疑似重复暂存等待确认；历史重复清理和其他新增入口的统一场景登记不在本次改造范围。
后台仍按当前项目/子产品范围做比较；提交人不等待判重，但后台大规模处理吞吐未做生产压测。SQLite写锁限制仍存在，生产MySQL锁兼容性仅做代码及DDL检查。
发布包含后端、前端产物与技能源码；服务器由维护者执行 scripts/update.sh 拉取并重启。本地验证未写入线上业务数据。
