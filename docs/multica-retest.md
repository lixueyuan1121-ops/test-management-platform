# Multica 反馈复测

入口：**对话测评 → Multica 复测**，也可从测评结果页点击“查看已推送 / 复测”。

## 使用流程

1. 选择项目，搜索或按原产品筛选已推送的结果。列表包含历史推送，不受测评结果页最近 500 条记录限制；勾选只作用于当前页。
2. 勾选反馈，点击“复测所选”。默认分别沿用每条原产品、模型、模式和思考深度。
3. 可勾选“修改产品”重新多选产品，或勾选“修改模型”填写新模型。覆盖配置应用到每条所选反馈；模型修改后留空表示沿用客户端当前模型。WorkBuddy/QWork 只携带模型，不携带纳米Work专用模式或思考深度。
4. 点击“创建并执行复测”，系统新建一个测评任务和执行批次，分配给支持相应产品的在线测评 runner。原结果、分享链接、判定及推送状态均保留。
5. 在“记录与对照”查看原判定及各次复测的产品、模型、状态、评分、理由和对话链接。“查看任务 / 判定”打开这条记录对应的任务和批次，可继续批量判定、生成综合评价。

复测提问、附件引用、验收标准读取原执行快照。用例库后来修改或删除不影响已有完整快照；缺少原提问快照时会明确阻止下发，避免使用已修改的题面冒充原输入。附件文件本身仍需可访问。

多轮会话会补齐原批次、原产品、原配置和原重复次数对应的完整上下文。不同配置、产品、重复执行之间不会串联。缺失或重复轮次会阻止下发。单轮仍各自独立。

有复测执行或判定中时禁止重复下发同一反馈；完成后可再次复测。绑定纳米Work目标设备的原任务复测仍要求原 runner 在线，避免切到另一台机器访问错误设备。新建任务默认不启用一条龙，执行完成后在任务中发起判定。后续按原基准复测仍从本入口发起，常规测评任务的再次执行使用用例库配置。

## 推送标题及存量数据

新推送标题使用北京时间当天日期，例如 `2026-09-18 【测评反馈】文件汇总缺失`。skill 模式直接使用此标题；HTTP 请求新增 `title` 字段；自定义 CLI 模板可使用 `{title}` 参数（占位符已按单个参数转义，无需再加引号）。

仅推送成功时保存推送时间。历史反馈自动纳入列表，未知日期显示“历史推送”；不会伪造日期或批量重命名已有 Multica 任务。数据库启动迁移仅增加可空字段和索引，保留存量数据。

## 本地验证

后端（在 `backend` 目录）：

```sh
PYTHONPATH=. .venv/bin/python scripts/test_eval_multica_retest.py
PYTHONPATH=. .venv/bin/python scripts/test_multica_skill.py
PYTHONPATH=. .venv/bin/python scripts/test_eval_multica_selection.py
```

前端先启动本地 Vite，再从仓库根目录运行：

```sh
UI_BASE_URL=http://127.0.0.1:5188 node frontend/tests/eval-multica-ui.cjs
UI_BASE_URL=http://127.0.0.1:5188 node frontend/tests/eval-results-ui.cjs
UI_BASE_URL=http://127.0.0.1:5188 node frontend/tests/eval-summary-status-ui.cjs
```

测试使用内存数据库、模拟在线设备和模拟 API，不创建真实 Multica 任务，不调用模型或执行真实用例。
