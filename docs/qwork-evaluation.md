# QWork 对话测评接入

已按本机 QWork 0.1.16（Electron 37.10.3）接入。与 WorkBuddy、纳米Work分别使用独立执行器、会话和调试端口。平台的任务、批次、判定及综合评价仍使用现有流程。

## 使用流程

1. 更新平台前后端和 runner 的完整代码。旧 runner 不声明 QWork 能力，无法误领 QWork 任务。
2. 在装有 QWork 的执行机配置 `tools/qalab-runner/.env`：

   ```dotenv
   # 保留纳米Work与WorkBuddy，并增加QWork。只装QWork时可填qwork。
   EVAL_ENGINES=workbuddy,qwork
   QWORK_EXE=/Applications/QWork.app
   QWORK_CDP_PORT=9336
   QWORK_INSPECT_PORT=9337
   # 可选，留空使用QWork模型列表中的默认模型
   # QWORK_MODEL=Deepseek-V4-Flash
   ```

   Windows 的 `QWORK_EXE` 填实际安装目录中的 `QWork.exe`。`EVAL_ENGINE=workbuddy` 等旧配置仍支持；`EVAL_ENGINES` 配置多个产品时优先。应在平台升级后启用新能力声明，避免旧后端拒绝新声明。

3. 确认 QWork 已登录。首次使用先正常退出手动打开的 QWork，再启动 `run-eval.sh` / `run-eval.cmd`。执行器会在需要执行 QWork 任务时带调试端口启动它；不会强行关闭用户已经打开的客户端。两个调试端口只监听本机。
4. 在「测评任务」新建/编辑任务时勾选 QWork，选择配置过 QWork 的执行机，或者自动调度。可同时勾选多个产品做横评。
5. 指定模型时，从 QWork 实际模型列表精确匹配显示名或内部 ID，忽略英文大小写；匹配失败会列出可选模型并停止发送，不会偷偷换模型。QWork 暂不接受纳米Work专有的对话模式、思考深度；纳米的组合执行仍只展开纳米任务。混合产品的非纳米模型字段可留空，分别使用各产品默认配置。
6. 「测评结果 → 详情 → 采集记录」查看阶段正文、工具参数与返回、完整性诊断和实际配置；「下载完整记录 JSON」用于深入分析。

## 采集范围

使用 QWork 客户端自己使用的 `workGui.sessions.history` 和 `events.onSessionEvent` 接口，避免页面虚拟列表、折叠内容、最后一段回复导致的遗漏。

| 数据 | 保存方式 |
| --- | --- |
| 用户消息、各阶段助手正文、最终回答 | 保留当前回合所有原生消息块，最终答案另存用于列表和判定 |
| 客户端提供的可见思考记录 | 保留原文及标准化文本；未提供的不推测补全 |
| 工具及 MCP | 工具 ID、名称、参数、返回原文、错误标志；缺少返回/成功标志时不伪造成功 |
| 实时事件 | 原生事件与接收时间，包括客户端公开的子任务事件；不将增量事件当成重复工具调用计数 |
| 执行信息 | 会话 ID、回合 ID、诊断 Trace ID、实际模型、开始/结束时间、终态 |
| 用量 | 输入/输出/缓存 Token 分类，积分原始结算状态；未结算不填零，QWork积分不称为纳米算力豆 |
| 文件信息 | 输入文件哈希、客户端文件变更和交付物清单快照；清单不等于实际文件内容已核验 |
| 异常 | 权限/补充回答请求、超时、取消失败、记录缺失和接口错误 |

多轮复用同一 QWork 会话，每轮按原生回合 ID 分开保存，并记录前序回合 ID。文件变更/交付物是会话快照，明确标注作用范围。无法确定回合归属时，仅保存诊断原文，不拿其他轮的内容填充本轮答案。

完整 JSON 先写入执行机 `eval/output/qwork/<run_id>/trace.json`，再上传平台，最后报告完成；数据库 `raw_message` 只保存索引及哈希，避免长工具输出撑爆 TEXT 字段。`result.json` 和 `report.json` 一并保留，便于故障定位。上传最多尝试三次，彻底失败时报告失败并提供本地证据目录；不会因此重复发送对话。

实时事件默认最多 5MB；超出会明确标记事件缺失，原生历史仍保留。完整上传受平台现有 20MB 限制，超出时完整原文留在执行机并报告上传失败，不静默裁剪后宣称完整。

### 权限与分享（2026-09-18）

- 旧版遇到任何权限或追问都立即报 `QWORK_INPUT_REQUIRED` 并取消任务。实际失败记录中的 Excel、Word 技能是在当前任务目录执行 `rm -rf _unpacked/unpacked` 后重新解包文档，触发了 QWork 的单次删除确认。
- 现在核验会话、工作目录、输入文件归属、QWork 内置技能路径和完整命令后，对已支持的临时解包清理点击原生弹窗“允许”，仅本次有效。等待请求消失和弹窗关闭后继续轮询，不重发题目。所有请求、处理结果保存在 `trace.permission_actions`。不能直接仅调用权限 IPC，否则客户端会留下过期弹窗挡住分享。
- 未支持的命令、工作区外操作、付费授权、真实补充问题保留人工处理窗口，默认 120 秒；在 QWork 处理后自动继续。超时错误包含实际权限摘要/问题，完整原文保留在 `pending_interactions`。仍受整轮 `taskTimeout` 限制，不设置“始终允许”。目前自动清理规则覆盖已实测的 Bash 文档技能命令；Windows/PowerShell 的其他命令走人工处理，未声称已真机适配。
- 每轮结束后打开当前会话的原生分享面板，核对完整回合数，将“全选”设为勾选状态，点击“复制链接”。验证链接是 QWork 分享且分享记录属于同一会话，再回填 `share_link`。已勾选时不再次点击，兼容侧栏收起状态。
- QWork 分享为快照。后续轮生成的新全选链接由平台同步给同项目、批次、认领、QWork 会话中的前序结果；答案、评分、判定状态不变。纳米Work/WorkBuddy 仍用各自策略。QWork 原生分享只纳入已完成回合；取消/未完成回合的诊断内容仍在完整 trace 中。
- 分享失败最多尝试两次，仅重试分享，不重跑题目；已完成回答仍正常回写，`reason` 和 `trace.share` 保存分享错误。运行中的旧 runner 需重启加载新代码；多轮链接同步需同时更新平台后端。

## 验证记录

- 本机 QWork 0.1.16 实测：首轮读取合成附件并返回唯一标识，续轮记住标识并追加指定内容。首轮 4 条消息、1 次工具调用、57 条实时事件；续轮 2 条消息、22 条事件，两个回合归属正确。真实记录只保存在本机临时目录，不纳入仓库。
- 自动验证模型大小写匹配、附件失败阻止发送、超时/权限等待保存部分内容、后续轮停止、上传重试、长文本保留、缺失字段及错误端口拒绝连接。
- 内存数据库验证三产品下发与能力心跳、旧 runner 隔离、纳米组合参数隔离；独立分发包验证包含所有 QWork 模块。
- 浏览器模拟接口验证产品勾选、单产品及三产品下发、采集记录和 JSON 下载，并回归纳米Work与WorkBuddy原有行为。
- Mac 已做真实客户端验证；Windows 启动参数和通用路径逻辑由测试覆盖，尚未在 Windows 真机运行 QWork。
- 2026-09-18 Mac QWork 0.1.16 真机回归：合成 Word 文档触发删除保护，原生弹窗仅本次允许后完成、关闭弹窗并复制分享链接；另一条两轮合成会话全选分享成功。浏览器夹具覆盖全选已勾选/未勾选、侧栏折叠、错误产品/会话链接、复制超时及权限内容不匹配。

同时补齐了当前仓库之前合入的 `SelectorAdmin.vue` 引用但未提交的 `probe-batch.js`，解除完整前端构建阻塞；包含 frame 隔离、候选唯一性与批量 key 去重测试。
