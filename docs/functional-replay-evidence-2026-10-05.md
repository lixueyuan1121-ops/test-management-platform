# 功能测试回填与回归一致性

本次改动围绕本地最终脚本与平台回归使用同一执行流程，保留现有业务断言、权限、用例去重及旧执行记录。不需要新增数据库列，证据保存在执行 payload 快照中。

## 已实现

- Runner 增加 `node runner.mjs --verify-import draft.json --output verified.json`。读取项目选择器快照，取得桌面锁，按队列相同的复位、前置导航、StepExecutor、截图和超时流程执行；每条连续两次通过后自动生成回填包。失败保留现场，不输出成功包，不认领线上任务或自动上传。
- 新回填包携带执行器内容指纹、执行方式、脚本与执行约定指纹、报告指纹和选择器快照。客户端、服务端核对实际数据，修改内容后须重新验证。外部结果仍标记外部实测，哈希仅证明内容一致性，不代表服务器独立证明本地执行。
- 用例详情和执行报告显示回归验证状态。“验证回归（2 次）”经过界面确认后下发两条严格队列执行；仅支持独立 GUI/E2E 用例，前置操作须写成步骤，断言须确定。严格模式禁止缺脚本/不支持动作时自动改用 Claude 兜底。
- 同一执行约定、同一执行器内容版本和平台/Node 环境连续两次严格队列通过才显示已验证。脚本、前置条件或选择器快照变化时重新计算；失败、人工纠偏、旧 Runner 无证据结果不计入。当前使用完整项目选择器快照，因此项目选择器变更也会触发重验。
- 报告区分脚本执行、Claude 前置导航、Claude 判定、Claude 兜底；展示脚本和执行器版本，以及执行版本是否与当前用例一致。复用已有用例时保留旧用例，原始导入脚本/快照另存，差异明确提示。
- 选择器不唯一时记录实际匹配数量、frame 范围和原始定位对象；保留失败截图。旧记录中的“匹配 N 个元素”也能显示为定位不唯一，提供匹配冲突入口。没有改用第一个元素，没有放宽断言。

## 使用与配套更新

先发布后端和前端，再更新并重启空闲设备上的 Runner，最后分发 `tools/skills/qalab-requirement-test`。源代码和正式前端产物分别提交到主分支，服务器执行 `scripts/update.sh` 后才算平台部署完成。既有正在执行的设备应等待空闲后更新。

新后端兼容旧回填包和旧 Runner，但旧结果没有新版认证。新版回填包不要删除 evidence 字段以适配旧服务器。技能文档给出草稿字段和原包提交方式；本地截图、追踪保存在回填 JSON 旁的 `.evidence-*` 目录，尚未作为云端图片上传。API 用例继续原来的 API 执行器流程。

“已验证”描述记录中的脚本、选择器与执行器组合，不保证其他应用版本、账号权限或所有机器必然成功；应用版本和实际验证范围仍由 environment/scope 记录。历史批次不会被新代码自动修复，需拿原始脚本定位目标并重新实测。

## 验证

- Runner：执行分支、严格模式、复位/前置条件、兜底标记、指纹变化、两次真实结果打包、失败不出成功包、桌面子进程超时/取消和原有逐步执行回归。
- Playwright：共享运行时与导出脚本的浏览器回归；复现可见文字被宽泛 XPath 匹配 18 次，确认没有点击且保留截图和结构化诊断。
- 后端：内存数据库覆盖导入、双次下发、执行证据校验、版本失效、人工纠偏/旧报告不认证；原异步导入、幂等、权限、终止、阻塞分类、历史按需加载回归。
- 前端：模拟接口下实际点击匹配冲突、版本提示、双次验证确认/下发；原终止和只读权限流程。开发验证使用内存生产编译，发布时另行构建并提交 `frontend/dist`。
- Skill：结构验证、macOS helper 单元测试、Node 指纹校验、Python/JavaScript 数字与 Unicode 指纹一致。当前机器没有 PowerShell，Windows 桥接修改未在 Windows 原生环境执行。

本次没有在真实业务应用上重新执行失败批次，也没有把模拟测试结果回填到生产平台。
