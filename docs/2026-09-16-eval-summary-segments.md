# 综合评价输入预算与分段汇总

综合评价原先把整批执行结果、思考与工具调用证据拼成一次模型请求。回答虽然有截断，但整批输入、工具轨迹和逐次试验统计没有统一上限。现在手动生成和一条龙自动生成共用以下流程。

## 实际流程

1. 读取所选批次的完整执行与判定结果，计算完整计划分母、按产品/维度统计和重复试验等权统计。模型只解释统计，不能平均分段通过率或根据摘要重算总数。缺失耗时保持未知；旧数据的文字耗时仍可转换使用。
2. 对每条记录的回答、思考、附件元数据、工具参数和返回证据设置限额。工具过程优先保留报错及相邻恢复步骤，摘要保留稳定样本编号和标题；删减处明确标注为平台截断，原始资料仍在执行明细。
3. 小批次在预算内直接生成报告。超过大小或条数上限的批次，按完整执行记录拆段，每条可评记录均进入一段，不直接丢弃尾部样本。
4. 逐段整理短证据摘要，先保留异常、低分和缺失证据，再记录成功做法与改进建议。摘要若仍不能装入最终请求，继续分组合并，直到满足最终请求预算。
5. 将全部分段证据摘要与平台完整统计合成原有结构的 HTML 综合评价。最终请求与中间请求执行同一大小检查；报告完成后才保存成功状态和分享码。

整个流程只生成综合评价，不重跑已完成的执行或判定。模型调用仍受现有全局槽位和单次超时约束；本实现串行处理分段，每完成一段即保存，不增加单任务模型并发。分段增加了调用次数，不能承诺任意批次都比原流程快；目的在于避免超大单次请求及失败后反复从头生成。

## 输入限制

```dotenv
EVAL_SUMMARY_MAX_INPUT_CHARS=48000
EVAL_SUMMARY_CHUNK_MAX_ITEMS=20
EVAL_SUMMARY_API_RETRIES=1
```

- 字符限制包括系统提示词；同时限制 UTF-8 字节数不超过字符上限的两倍，默认 96,000 字节。这是确定的文本大小预算，不是假定某模型的精确 token 数。
- 字符配置约束在 12,000–96,000，单段记录数约束在 2–40。产品对比、重复执行中的每条执行记录都计入分段条数。
- 中间摘要默认最多 4,000 字符、8,000 UTF-8 字节，低预算配置会进一步收紧；过长输出有明确截断标记，再进入下一层。
- 完整统计保留整体分母与质量指标，去掉逐次试验的完整 run_id 列表。分组极多时限制分组明细并标明省略数量，不改写整体指标。完整记录仍可在执行明细中查询。
- 请求发出前再次检查预算；日志记录任务、批次、阶段、尝试次数和输入长度，不记录整批 prompt 正文。

## 失败与续跑

每个分段、中间合并、最终报告遇到 API Error 默认额外重试一次，只重试当前调用，丢弃失败尝试的半段正文。重试耗尽则记录具体失败阶段与错误，已有分段摘要继续保存；不会将部分分析标为完整报告。

点击重新生成时，相同批次、资料版本、任务说明、模型配置和输入预算下可复用已完成摘要，最终报告仍重新生成。重新判定、修改结果或切换模型后会使相应摘要失效；历史批次与当前批次隔离。正常重判会作废生成令牌，使旧流程停止；最终落库还会完整核对来源版本，防止旧结果覆盖新判定。

页面显示分段完成数量、当前处理段、逐层合并进度、最终评价生成、复用数量、重试与失败原因。刷新或关闭后再打开可恢复这些状态。状态轮询不返回分段摘要正文。

## 更新与验证

需要同时更新前后端并重启后端。启动时幂等创建 `eval_summary_checkpoint` 表，并补充此前状态展示所需的 `summary_progress` 列；无须清理已有报告或更新客户端 Runner。

离线回归包含：84 条长轨迹样本完整分段、1,000 段摘要多层归并、中文/emoji 字节限制、超长单条和附件、过程报错/恢复保留、完整分母、当前段重试、失败后续跑、最终汇总失败只重跑最终阶段、结果/模型变化、历史隔离、最终版本校验、迁移及页面各阶段展示。模型与通知均使用测试替身，未将真实线上测评内容发给模型。

分段、状态、API Error 重试、结果一致性的合并回归共 70 项通过；另通过一条龙编排、分享链接、AI 队列、失败状态收口、原报告章节/过程证据、历史耗时和浏览器状态回归。
