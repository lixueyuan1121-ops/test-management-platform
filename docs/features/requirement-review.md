# AI 测试助手：需求澄清与验收确认

需求生成用例前增加一个可保存、可恢复的评审阶段。适用于文字、图文混排 PRD、截图、权限矩阵、流程图及原型说明。

## 使用流程

1. 选择项目及关联任务，粘贴文字、读取链接或上传资料。支持在已有正文上「补充需求图片」。
2. 点击「分析需求」。系统先识别图片，再结合正文整理本期范围、关键流程、原子规则和需要拍板的问题。
3. 对照「图片与图表」里的原图与识别结果，在规则中确认前提、触发、预期、禁止行为、边界、验收条件及原文依据。推导内容不会冒充原文。
4. 填写澄清结论，并把结论落实到相关规则。每条规则选择待确认、确认本期验收或本期排除；排除需要原因。存在图片识别不确定、素材缺失或截断时，需要填写处理说明。
5. 核对整体范围后确认，产生不可变的验收版本。只有已确认的规则进入用例生成；未确认及排除规则在覆盖结果中单独展示。
6. 在结果或用例库详情中，对照验收条件及依据检查用例。覆盖按验收条件统计，区分生成关联、人工核验和缺失。采纳不会表示测试执行通过；否决后该用例不再贡献覆盖，修改步骤或预期后需要重新采纳核验。

修改原始需求、重新导入图片或修改规则后，必须重新分析或确认。历史用例保持关联当时的确认版本，不会随新草稿改变。历史分析可从当前项目、任务下恢复，刷新页面或停止等待不会删除后台成果。

## 图片处理

| 来源 | 处理方式 |
|---|---|
| 飞书 Docx / Wiki 中的 Docx | 读取全文及分页文档块，下载嵌入图片，保留所在文本位置及文档块链接 |
| Word `.docx` | 按正文顺序读取段落、表格行列和嵌入图片 |
| PDF | 提取文本，同时渲染页面给视觉模型，覆盖扫描页、矢量图和页面上的表格 |
| PNG / JPG / WebP / GIF / BMP | 直接识别；长截图分片并保留重叠区域，多帧图片仅首帧且显式提示 |
| 普通网页 | 读取静态文本及可访问的图片，下载和跳转沿用公共地址校验 |

识别保留表格行列、否定词、数值、脚注及流程箭头关系；不清楚的内容标记不确定。图片读取失败仍在结果中展示，不能静默当作需求不存在。

单次上传不超过 5MB；正文编辑区最多 60,000 字，完整导入文本另存。最多处理 40 个图片片段、40 页 PDF，长页分片也占图片额度；图片解码后总量最多 40MB。超限会提示拆分。飞书画板、嵌入电子表格、附件及 Word 页眉页脚等未覆盖对象会提示补充截图、PDF 或文字；动态网页、受权限限制的素材也需要补充。

原图经登录及来源/项目权限检查后读取，不放入公开上传目录。补充图片会建立新的来源快照，旧评审中的图片不被替换。

## 运行与配置

- 后端安装更新后的 `backend/requirements.txt`，新增 Pillow、pypdfium2。启动时通过现有 `Base.metadata.create_all` 创建五张新表，不修改现有业务表。生产数据库账号需具备建表权限；图片存储应为 MySQL 的大字段配置合适的包大小。
- Claude 通过标准多模态消息传入图片，继续禁用文件、命令及网络工具。选用其他文字生成引擎时，若该引擎未配置视觉能力，会使用已启用的 Claude 读取图片。
- OpenAI 兼容网关可配置 `DEEPSEEK_VISION_MODEL`，使用同一已配置网关和凭据调用视觉模型。留空不会把图片发给默认文字模型；无可用视觉引擎时显示读取失败及配置提示。
- 飞书需沿用平台的应用凭据，开放文档、文档块及素材下载权限，并将资料共享给该应用。文档正文可访问不保证图片素材有下载权限。
- 分析及生成走现有 AI 作业队列；分析完成或失败后的图片结果可恢复查看。大量图片会增加模型耗时。新作业在队列字段中保存引用编号，长原文、规则及图片保存在新表的大字段中。
- `/api/ai/testcases` 新请求必须携带当前任务的 `baseline_id`；旧历史记录仍可查看。前后端需一起更新，已有调用此接口的客户端需先完成分析和确认。
