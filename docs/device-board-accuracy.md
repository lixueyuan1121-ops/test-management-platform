# 设备看板统计与任务归属

## 修正内容

- 功能测试仅在下发时选择 `runner=auto` 才允许离线后自动改派。显式指定机器的任务保持原归属，自动重试继承此设置。历史记录没有调度意图快照，默认不自动改派。
- 排队按当前派遣的 runner 统计；执行记录优先按实际认领设备 ID 统计。只有唯一匹配时才用旧 runner 名称归属，不把同名历史数据重复算到多台机器。
- 今日通过/失败以 `finished_at` 为准，避免昨天下发、今天完成的任务漏算，也避免判定/人工修改把旧结果挪到今天。历史没有此字段时只能回退 `updated_at`，不能保证还原原始完成时间。
- 执行时长从 `started_at` 算，旧执行回退 `updated_at`，不从创建时间算。
- 新功能 runner 每分钟发送执行心跳。超过三分钟没有执行心跳的记录显示为“状态待确认”，不算正常执行中，不凭此强制机器在线。旧 runner 没有执行心跳时沿用功能测试两小时、测评六小时的兼容窗口。
- 多轮测评只显示当前未完成轮次在执行，后续已认领轮次算本机排队；前轮回填后更新下一轮开始时间。
- 页面刷新失败明确显示上次数据，避免静默展示过时快照。

## 上线与历史数据

先部署后端并重启，启动迁移补充执行跟踪字段；再更新功能和测评 runner，最后更新前端。

本次不自动撤销已经发生的历史改派，也不修改历史结果归属。旧版功能改派只在 `exec_run.reason` 留下 `[自动改派] 原设备 ... 离线,改派到 ...`，且后续执行回填会覆盖 reason。因此不能仅凭当前 runner 推断历史最初指定的设备，更不能把已经执行过的结果移回原设备。

线上核查目标设备时，应先查看该 runner 的 pending 记录及 reason 中的自动改派标记，核对批次来源和下发意图。只对确认误派且尚未认领的记录恢复原归属；无法确认的记录保留，不批量猜测回滚。

验证：`python -m scripts.test_device_board_accuracy`、`python -m scripts.test_device_overview`、`python -m scripts.test_dispatcher`（在 backend 虚拟环境中运行）。
