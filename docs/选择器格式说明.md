# 语义选择器格式说明

> 描述测试平台里「语义选择器」的生成与入库格式。DB（`selector_key` / `selector_scope` 表）是唯一事实源；内置 `tools/qalab-runner/gui-mcp/selectors.json` 是可一次性导入的旧注册表，两者结构一致。

## 1. 整体结构

选择器以「语义 key → 候选定位策略列表」的形式组织：

```json
{
  "vmIframe": "iframe[src*=\".work.n.cn\"]",
  "coreKeys": ["homepageTitle", "navHome", "loginSubmit", "..."],
  "registry": {
    "loginSubmit": {
      "frame": "shell",
      "desc": "登录 提交按钮",
      "candidates": [
        { "by": "css", "value": "input[type=submit]" }
      ]
    }
  }
}
```

- **`vmIframe`**：被测页内嵌 iframe 的定位（对应 `selector_scope.vm_iframe`）。
- **`coreKeys`**：核心 key 名数组（进入/首页/登录类，L3 巡检重点）。
- **`registry`**：`key → 定义` 的映射，是主体。

## 2. 单个 key 的字段

对应 `selector_key` 表一行 / `registry` 里一项：

| 字段 | 类型 | 含义 |
|---|---|---|
| `key` | string(≤64) | 语义名，作用域内唯一（如 `loginSubmit`） |
| `frame` | string | 归属：`auto`（默认）/ `shell`（外层壳）/ `iframe`、`vm`（内嵌页） |
| `page` | string | 所属页面，用于按页面收窄注入（可空=通用） |
| `desc` | string | 人类可读描述 |
| `candidates` | JSON 数组 | 候选定位策略，按稳定性排序，命中即用 |

**作用域**：按 `(project_id, sub_product)` 分域。`sub_product=""` 为**项目级共享**，非空为**子产品专属**（同名 key 子产品覆盖共享）。

## 3. 候选（candidate）格式 —— 核心

每条候选是 `{ by, value }`（`role` 类型可带 `name`）：

```json
{ "by": "testid", "value": "login-btn" }
```

**`by` 的合法取值（6 种）**，按稳定性从高到低：

| by | 生成来源 | value 示例 | 稳定性 |
|---|---|---|---|
| `testid` | `data-testid` / `data-test` | `login` | ✅ 最稳 |
| `css` | `#id` / `[name=x]` / BEM class | `input[name=userName]` | ✅ 稳定 |
| `label` | `aria-label` | `关闭` | ✅ 稳定 |
| `placeholder` | `placeholder` 属性 | `手机号/用户名/邮箱` | ✅ 稳定 |
| `role` | `role`+`aria-label`（带 `name`） | `by:role, value:button, name:提交` | ⚠️ 脆弱 |
| `text` | 元素可见文本（2–20 字） | `登录` | ⚠️ 脆弱 |

- **稳定 vs 脆弱**：`text` / `role` 判为**脆弱**（`getByText` 默认子串匹配、role 依赖文案，易失效且多命中触发 strict 违例）。运行期 `order_candidates` 会把脆弱候选降到链尾。
- **有效候选**：必须 `by` ∈ 上述 6 种且 `value` 非空。否则视为无效（如 `{}`、`{"by":"css"}` 缺 value），入库时被 schema 校验拒绝。

## 4. 生成过程（runner 侧 `genCandidates`）

探测某元素时，按下列顺序为它生成候选并打分（score 高→稳），排序后落库：

```
testid(100) → id(90) → aria-label(80) → name(75) → placeholder(70)
→ role+aria(68) → BEM class(60)/普通 class(45) → text(40) → tag[type](30)
```

即：一个元素通常会产出**多条**候选，从最稳的 `testid` 一直兜底到 `text`；runner 定位时按此顺序逐条尝试，命中即用。

## 5. 一个完整实例

```json
"loginUserName": {
  "frame": "shell",
  "desc": "登录 用户名/手机号 输入框",
  "candidates": [
    { "by": "css", "value": "input[name=userName]" },
    { "by": "placeholder", "value": "手机号/用户名/邮箱" }
  ]
}
```
