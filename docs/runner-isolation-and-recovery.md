# Runner 隔离与队列恢复（2026-09-23）

设备看板的“测评任务”和“对话测评”原来分别来自当前任务类型和在线执行器类型，实际指同一测评服务。现在合并去重，统一为“对话测评”。功能和测评服务都在线时，各显示一个标签，任务依次执行。

## 本次修复

- 测评认领与功能测试、探测、录制锁同一设备行，检查两类执行队列。测评共享 token 也不能绕过已登记设备的占用检查。回收旧执行时不再中途提交事务、提前释放设备锁。
- 新版功能和测评 runner 使用本机回环端口 `127.0.0.1:19783` 互斥，即使在不同目录、用不同 runner ID 启动也不能同时控制桌面。进程退出后由系统释放锁；录制期间一直持锁。启动客户端、切换页面、复位和自更新均在本机锁内进行。
- 测评先整组认领，再初始化客户端。每轮处理一个完整会话，释放桌面后再轮询；多轮会话不中途让出桌面。异常退出会尝试结束已认领但未回填的轮次。
- 在线能力按两个服务各自的心跳维护，不再由最近一次轮询覆盖另一服务的能力。
- 新客户端心跳失联超过 5 分钟后可回收，后台每分钟巡检。旧客户端没有可信心跳时仍保留功能 2 小时、测评 6 小时的兼容窗口，避免误结束长任务。持续心跳的长任务不会仅因执行时间长而被回收。
- 设备看板和“我的执行设备”新增“清理排队”。设备所有者或平台管理员可结束该设备尚未开始的任务，保留历史记录和执行中任务。功能记录沿用 `blocked` 状态、标记 `fail_kind=cancelled`；测评记录为 `cancelled`。不会仅因设备离线就自动删掉排队任务。
- 新 Windows 启动脚本使用 ASCII、CRLF，从 `.env` 获取配置，不再用脚本内的占位值覆盖设备身份。自更新会修复旧 `run.cmd` 的 UTF-8 中文注释和换行，保留原有配置与首次备份 `run.cmd.encoding-backup`；无法可靠识别编码的文件不自动修改。备份不进入升级包。

## 生效步骤

1. 发布并重启后端，更新前端；本次不新增数据库字段或枚举。
2. 在每台执行机结束旧的功能/测评进程，再启动升级后的 runner。两边都必须升级，本机互斥才完整生效。新安装统一填写根目录 `.env`；存量脚本的身份配置会保留。
3. 在设备看板核对排队项，再点击“清理排队”结束不需要继续执行的历史队列；需要执行的任务可以重新下发。此次代码修改未操作线上队列。

旧启动脚本不被升级包直接覆盖；修复旧 `run.cmd` 后，下次启动生效。不能只更新服务器就假设所有正在运行的旧进程已经获得互斥能力。

## 验证范围

隔离数据库 HTTP 回归覆盖双向互斥、共享身份、失联回收、活跃长任务保护、清理权限/幂等/归属，以及多产品测评顺序认领。双 Node 进程测试覆盖互斥和强杀后的锁释放。独立 ZIP 安装、自更新保留配置、启动模块加载、测评客户端协议测试通过。两个修改页面通过 Vue SFC 脚本与模板编译。

验证环境为 macOS；没有在截图中的 Windows 电脑上复现和复测。Windows 文本编码修复已测试，但实际客户端 CDP 超时是否还存在，需要更新后的真机日志确认，不能仅凭截图归因于单一因素。
