# 对话测评升级与验证记录

日期：2026-09-12。基于 `957bb76a` 的本地实现，接续同目录的 Workbuddy-bench 评审。本记录不表示已提交或部署。

## 流程变化

1. 默认仍为一次执行。任务执行页可选择每题独立执行 1～5 次；按产品、A/B、trial 分开派发，多轮题每次使用完整的新会话组。执行重试不增加独立 trial 数。
2. 派发时保存题目、附件信息、验收规则、计划执行集合及配置快照和题库哈希。每次执行记录请求与实际读取的配置、Runner 哈希和输入附件哈希。显式指定的模型或模式必须核对成功，否则记录配置错误；WorkBuddy 不支持的模式和深度在派发前拒绝。
3. 判定输入补充原始问题及同批次、同产品、同 A/B、同 trial 的此前轮次。运行快照优先于当前题库，因此改题、删题不会重写已有题目上下文和历史维度。
4. 每次判定创建独立版本，留存提示词、规则版本、全部评分票据与结果。重判清除当前旧分数和复核标记；原结果与原复核仍可查询。人工复核使用判定版本校验，避免并发重判后把旧反馈写到新版本上。
5. 题目可选产物检查：文件可解析、文本包含、Sheet 存在、单元格公式、单元格值和最少页数。Runner 采集实际文件，后端依据文件字节核验，证据保存文件哈希。明确违反硬性检查会判失败并限制评分；未取得文件或当前无法核验时显示证据不足。

## 结果变化

| 指标 | 口径 |
| --- | --- |
| 有效样本通过率 | pass / (pass + fail) |
| 判定覆盖率 | (pass + fail) / 计划样本数；批次实验按冻结集合补入缺失记录 |
| 已确认成功占比 | pass / 计划样本数 |
| 重复执行成功频率 | 先在同题完整会话的各次执行内统计，再对题目等权平均 |
| 成本 | 区分已知小数、真实零值和未采集，展示成本覆盖率、重试成本及包含重试的合计 |

例如 10 条执行仅 1 条 pass、其余 9 条判定 error：显示有效样本通过率 100%、覆盖率 10%、已确认成功占比 10%，并保留错误数量。不能据此得出整体成功率为 100% 的结论。

任务详情、结果分析、共享及导出报告加入上述口径。独立重复执行会增加运行时间和算力消耗；可选文件核验会增加采集和判定耗时。旧历史结果不会自动重判，使用新规则重判后可能得到不同分数。

## 当前边界与发布要求

- 实际产物采集目前支持当前回答提供的公开 HTTP(S) 文件服务链接，并带相应域的浏览器 Cookie。客户端本地路径、blob URL 或仅通过界面按钮触发的下载尚未支持；不把这些采集失败记成产品能力不达标。
- 单文件上限 20 MB，单次采集最多 10 个链接并有时间预算。Office 校验属于格式和结构核验；未加入视觉排版评分。Word 页数需要渲染，当前返回无法核验；Excel 公式值读取保存的计算缓存，不执行公式。判定器实际模型名若服务未返回，保持未知，仅保存请求配置。
- 未运行完整 Workbuddy-bench 题库，也未完成 20～30 道真实 Office/Web 试点。这次实现提供规则配置和执行能力，真实题目的规则应在试点中逐题确认。
- 后端、前端和 Runner 需要配套更新。后端启动迁移会创建实验、判定、复核和产物表，并增加字段及 MySQL 大文本容量；真实发布前需在目标数据库验证迁移及配置持久化的产物存储目录。
- 发布后应使用小批量真实任务验证两个客户端的模型选择、多轮执行、算力豆刷新回填和实际文件下载，再逐步扩大重复执行批次。当前本地回归不能替代这项真实环境验收。
