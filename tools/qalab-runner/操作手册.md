# qalab-runner 操作手册(执行机操作员版)

> 面向**要在自己电脑上跑 runner、把平台勾选的用例执行掉并回写结果**的同事。
> 覆盖功能用例执行这条主线(gui / e2e / api / cli),含最新的**结构化 script 确定性执行**、
> **用例间复位自愈**、**fail_kind 判读**、以及并列的**探测(probe)/ 性能采集(perf)**两条队列。
>
> 和其他文档的关系:本文是**操作 SOP**(从零跑通 + 日常运维 + 排障);`DEPLOY.md` 是精简部署卡片、
> `README.md` 讲整体设计、`gui-mcp/README.md` 讲选择器库、`eval/部署手册.md` 是**对话测评**那条独立线(不在本文范围)。
> 内容有出入时**以代码与本文为准**(README 部分段落偏旧)。

---

## 0. 一分钟看懂 runner 在干什么

runner 是一个常驻本机的 Node 进程,**主动轮询**平台三条队列并回写结果(平台/客户端零侵入,绕开一切入站网络问题):

```
qalab 平台                    runner.mjs(本机 node,每 5s 一轮)
  │  ①在平台勾选用例下发到你的设备
  │                             ├─ exec 队列  → 执行功能用例(gui/e2e/api/cli),回写 pass/fail
  │  ②GET 拉 pending → claim ──┼─ probe 队列 → 探测/巡检选择器(给"选择器管理"页用)
  │                             └─ perf 队列  → 性能采集(可选)
  │  ③PATCH 回写 {verdict, fail_kind, reason, evidence, report}
  ▼
被测客户端 Namiwork(纳米Work,Electron;UI=work.n.cn)—— 仅 gui/e2e 用例需要
```

一条 gui/e2e/api 用例进来,runner 优先走**确定性执行器**(按结构化 `script` 逐步执行、直接算断言,不经大模型,快/稳/省/可复现);
用例没有结构化 `script` 时,才降级用 **Claude Code(headless)**兜底判定。cli 用例始终走 Claude + Bash。

> 你**不需要**懂这些内部细节也能跑起来,但看结果、排障时理解它们很有用(见 §7)。

## 1. 前置依赖(按你要跑的用例类型装)

| 依赖 | 用途 | 只跑 api/cli | 要跑 gui/e2e | 装法(Mac / Windows) |
|---|---|:---:|:---:|---|
| **Node.js 18+** | runner 运行时(用内置 fetch,零第三方依赖) | ✅必装 | ✅必装 | `brew install node` / 官网安装包(勾选加入 PATH) |
| **Claude Code CLI** | 无结构化 script 时的兜底执行大脑,须已登录 | ✅必装 | ✅必装 | 装好后 `claude -p "echo hi"` 能无交互输出 |
| **gui-mcp 依赖** | GUI 定位引擎 / 语义选择器 | — | ✅必装 | 在 `gui-mcp/` 下 `npm install` |
| **被测客户端 Namiwork** | 被测对象(Electron,带 CDP 调试端口) | — | ✅必装 | Mac:`/Applications/Namiwork.app`;Windows:记住 `namiclaw.exe` 路径 |

> runner 本体零第三方依赖(纯 Node 内置模块)。只跑 api/cli 时,可跳过 gui-mcp 依赖和被测客户端。

## 2. 一次性安装

```bash
# 1) 进入本目录(整个 tools/qalab-runner/ 拷到你电脑,或 git clone 后 cd 进来)
cd qalab-runner

# 2) 装 gui-mcp 依赖(playwright-core 不下载浏览器,连的是被测客户端自带 Chromium;仅 gui/e2e 需要)
cd gui-mcp && npm install && cd ..

# 3) 确认 Claude Code 能无交互跑
claude -p "echo hi"

# 4) 从样例建配置
cp .env.example .env        # Windows: copy .env.example .env
```

> **不要**从别人机器拷 `.env`(每台配置不同)和 `node_modules`(体积大、平台相关,本机重装)。`.gitignore` 已忽略这些。

## 3. 注册设备拿 token,填 `.env`

1. 登录测试平台 → 左侧 **任务执行 → 我的设备** → **注册设备**:填 `runner_id`(如 `你的名-mac`)和设备名。
2. 复制弹出的**专属 token**(只显示一次,关掉就没了)。
3. 编辑本机 `.env`:

```ini
# ---- 平台连接 ----
BASE_URL=https://qalab.claw.qihoo.net      # 平台后端地址(以管理员给的为准)
RUNNER_TOKEN=<第 2 步复制的设备专属 token>
RUNNER_ID=你的名-mac                        # 必须与注册时填的 runner_id 完全一致,否则拉不到派给你的用例
POLL_MS=5000                                # 轮询间隔(ms),一般不用改

# ---- Claude Code ----
CLAUDE_BIN=claude                           # claude 不在 PATH 时填绝对路径
CLAUDE_TIMEOUT_MS=240000                    # 单条用例调 claude 的硬超时(ms),卡死自动杀掉判 fail

# ---- 被测客户端(仅 gui/e2e 需要;不跑 gui 留空) ----
# Mac 指向 .app 内可执行文件;Windows 指向 .exe
NAMICLAW_EXE=/Applications/Namiwork.app/Contents/MacOS/Namiwork
CDP_PORT=9222                               # 被测客户端调试端口,一般不用改

# ---- 可选 ----
# RESET_BETWEEN_CASES=1                      # gui/e2e 用例间是否复位(默认开;填 0 关闭,见 §7.3)
# PERFDOG_DIR=                               # 性能采集引擎目录(跑 perf 才填,见 §8.2)
# REPORT_SET_ID=
```

> Windows 的 `NAMICLAW_EXE` 形如 `D:\Program Files\namiclaw\Application\namiclaw.exe`。

**token 末尾别混入空格 / 换行**:从网页复制常带隐藏字符。runner 已做去 BOM / 去 `\r` / 剥引号的清洗,但仍建议粘贴后检查一遍——`Bearer xxx\r` 会让平台返回 **401**(踩过)。

## 4. 启动

| | Mac / Linux | Windows |
|---|---|---|
| 首次赋权 | `chmod +x run.sh` | — |
| 正常启动 | `./run.sh` | `node runner.mjs`(推荐)或 `run.cmd` |
| 只验连通(不真跑) | `./run.sh --dry` | `node runner.mjs --dry` |

启动后应看到:

```
runner 启动 base=https://qalab.claw.qihoo.net runner=你的名-mac dry=false
perf 采集就绪 perfdog=...
```

之后每 5s 轮询一次。**保持这个窗口开着**,它就是你的执行机(无人值守跑,进程崩了会自动兜底继续,见 §9)。

> ⚠️ **Windows 用 `run.cmd` 的坑**:`run.cmd` 顶部用 `set` 硬编码了 `BASE_URL/RUNNER_ID/RUNNER_TOKEN/...`,
> 且这些**会覆盖 `.env` 同名项**(runner 的 `.env` 加载器"不覆盖已存在的环境变量")。
> 所以 Windows 上**要么**改 `run.cmd` 顶部那几行填真值,**要么**直接 `node runner.mjs` 让 `.env` 生效(推荐,和 Mac 一致)。
> 若照着 §3 填了 `.env` 却仍 401,多半是 `run.cmd` 里的占位 token 赢了 `.env`。

### `--dry` 先焊死"平台↔runner"链路(强烈建议第一次这么做)

`--dry` 只做**拉取 → claim → 回写假 pass**,不调 Claude、不碰被测客户端。让管理员在平台放一条 pending 派给你,
你 `--dry` 启动能看到它被拉到并置成 pass —— 这步通了,说明 token / runner_id / 网络都对,再去掉 `--dry` 接真实用例。

## 5. 平台侧怎么把用例下发到你

在平台的**用例库 / 已采纳用例 / 任务清单**里勾选用例 → **执行机下拉选你自己的设备**(即 `RUNNER_ID`)→ 发送。
你的 runner 下一轮(≤5s)就会拉到、执行、回写。

- 平台**不强绑定** kind ↔ 机器:派哪台就哪台执行,用例类型(gui/e2e/api/cli)来自用例自身的 `exec_kind`。
- **manual(人工/不可自动化)用例平台不会派给设备**;万一漏派到执行机,runner 会直接判 fail 并提示"应在平台改判类型或取消下发",不会空跑。

## 6. 看结果:一条用例回写了什么

每条用例执行完,平台对应用例会更新这些字段(你在平台上就能看到):

| 字段 | 含义 |
|---|---|
| `verdict` | `pass` / `fail` |
| `fail_kind` | **失败归类**(见 §7.4):`business`=真功能问题;`selector`=环境/定位阻塞(不计功能失败率);pass 时为空 |
| `reason` | 判定依据 / 失败原因(一句话) |
| `duration_ms` | 本条耗时 |
| `report` | **逐步执行报告**(gui/e2e 结构化执行时产):每步 `{no, action, desc, ok, error?}` + 关键步/失败步**截图** |
| `evidence_url` | 证据(截图路径 / URL) |

截图不塞进文本字段(MySQL 5.6 的 TEXT 只有 64KB,base64 会被截断),而是**逐张走独立上传端点**换成 URL 落库,平台直接显示。

## 7. 执行机制详解(排障必读)

### 7.1 五种用例类型(kind)

| kind | 怎么跑 | 需要被测客户端 |
|---|---|:---:|
| **gui** | 有结构化 `script` → 确定性执行器逐步跑;无 → Claude 用 `mcp__gui__*` 工具(先 `gui_connect`→`gui_list_keys`→按语义 key 定位断言) | ✅ |
| **e2e** | 同 gui(多步端到端) | ✅ |
| **api** | 有 `script` → api 执行器(不经 LLM);无 → Claude 用 Bash 跑 curl/fetch 验接口 | — |
| **cli** | 始终 Claude + Bash:起进程、校验退出码/输出 | — |
| **manual** | 不执行,直接 fail 提示(见 §5) | — |

### 7.2 确定性执行 vs Claude 兜底

- 用例带**结构化 `script`**(平台在用例上维护好的步骤数组)时,runner 用 `step-executor.mjs`(gui/e2e)或
  `api-executor.mjs`(api)**确定性执行**:`assert_*` 步直接算 pass/fail,快、稳、省、可复现,不受大模型主观性影响。
  支持的动作:`connect / click / hover / fill / wait_for / wait_response / get_text / screenshot / goto`,
  断言:`assert_text`(等于/包含,可 `negate`)、`assert_visible`、`assert_absent`(否定式:应消失),
  以及 `judge`(主观判定:把前面步骤抓到的文本喂给 claude 只判这一步)。
- 用例**没有 script**、或 script 里出现执行器不认识的动作 → **整条降级回 Claude** 兜底判定(日志会打 `script 需降级:...`)。
- **判定质量**:能确定性断言就别让大模型"看一眼觉得对"。用例设计上优先 `assert_text` / 退出码 / 接口响应等硬断言。

### 7.3 gui/e2e 用例间的「复位自愈」

为避免上一条用例的选中/弹窗/输入残留污染下一条,每条 gui/e2e 用例执行**前**会自动复位(默认开,`RESET_BETWEEN_CASES=0` 可关):

1. **reload 复位**回首页(失败重试);
2. **掉登录检测**:若复位后出现登录弹窗 → 判 `fail`(`fail_kind=selector`),`reason` 提示 **"执行机会话可能已过期,请在执行机重新登录被测客户端"**;
3. **首页就绪门禁**:等首页锚点(如问候标题)出现;没停稳时**分层自愈**,从无害到有副作用逐招试、每招后重探:
   - ① **页面层 ESC**:关网页模态/浮层(快、无害);
   - ② **OS 级 ESC**:关挡住客户端的**系统窗**(如误触发的文件资源管理器)。Mac 走 `osascript`(需授予**辅助功能**权限,否则静默跳过);Windows 走 PowerShell `SendKeys`;
   - ③ **点侧栏「新建任务/新建对话」**:开一个干净会话回首页(有副作用,放最后);
   - 逐招都救不回 → 判 `fail`(`fail_kind=selector`,"首页未停稳,跳过执行以免空跑")。

> 复位类失败都归 `selector`(环境阻塞),**不计入功能失败率**——它说明的是执行机状态问题,不是被测功能有 bug。

### 7.4 fail_kind 怎么读(判 fail 时先看这个)

| fail_kind | 含义 | 该找谁 |
|---|---|---|
| `business` | 断言不通过(如期望文本≠实际、该出现的元素没出现) | **真功能问题**,提给开发/记缺陷 |
| `selector` | 定位不到元素、复位失败、掉登录、CDP 未起、runner 异常等 | **环境/执行机问题**,按 §10 自查或找 runner 维护者 |

后端会把 `selector` 类映射成 **blocked**,不拉低功能通过率统计。所以看到一片 fail 先分清是"功能坏了"还是"执行机没跑起来"。

## 8. 额外能力(按需)

### 8.1 探测队列(probe)—— 给「选择器管理」用

runner 除了跑用例,还并列处理平台的**探测队列**(和 exec 用同一 token / runner):

- **discover**:扫当前页可交互元素,产出按稳定性排序的**候选选择器** + 整页截图(供网页叠框标注)。
- **verify**:校验当前作用域已登记的语义 key 是否还命中当前页(改版后哪些 key 失效)。

探测同样需要被测客户端带 CDP 在跑(没起会自动冷启动)。这条队列由平台的选择器管理页触发,你**无需手动操作**,保持 runner 常驻即可。选择器库的更新方式见 `gui-mcp/README.md`。

### 8.2 性能采集(perf)

perf 采集内置在 runner 里,共用同一进程/配置/token:

- 前提:被测应用在本机运行;采集引擎 `nami-perfdog` 随分发包同目录(或用 `PERFDOG_DIR` 指定)。
- 平台下发长监控任务 → runner 自动 claim 并上传;交互式场景按控制页提示操作后点"继续"。
- **本地补传**:`node runner.mjs upload [目录]` 或 `node runner.mjs upload --all`。
- 采集期间该 runner 不 claim test/probe 任务(一次只做一件)。

## 9. 日常运维

- **常驻运行**:`run.sh` / `node runner.mjs` 保持窗口开着即可。runner 有进程级兜底——任何漏网异常/未捕获拒绝**只记日志、不退出**,继续轮询(无人值守进程崩了会导致后续用例全停摆且不回写,所以刻意做了兜底)。想真后台常驻,可用 `nohup ./run.sh &` / `tmux` / `pm2` 等自行托管。
- **升级 runner / 选择器库**:`git pull` 即可(选择器库 `gui-mcp/selectors.json` 随仓库走;平台侧若配了 DB 注册表,runner 会在执行/探测前自动拉取合并,拉不到时回落内置文件)。拉完重启 runner。
- **token 泄露 / 换机**:在「我的设备」**重置 token**,更新 `.env` 后重启。
- **冷启动会打断你手动开的客户端**:跑 gui 用例前 runner 会**杀掉旧客户端进程**再带调试端口重启它(单实例锁所致)。你自己在用客户端时要留意。
- **被测客户端保持登录**:冷启动一般沿用已保存会话;掉登录时(见 §7.3)需你在执行机手动重新登录一次。

## 10. 故障排查速查表

| 现象 | 处理 |
|---|---|
| 启动即 401 / 拉不到用例 | ①`RUNNER_TOKEN` 是否正确、末尾无空格/换行;②`RUNNER_ID` 是否和平台注册的完全一致;③**Windows**:是不是 `run.cmd` 里的占位 token 覆盖了 `.env`(见 §4),改用 `node runner.mjs` |
| `--dry` 都拉不到 | 确认管理员已在平台把 pending 用例派到你的 `RUNNER_ID`;确认 `BASE_URL` 正确、网络能通 |
| `无法启动 claude` | `claude` 不在 PATH → `.env` 里 `CLAUDE_BIN` 填绝对路径;先 `claude -p "echo hi"` 自测 |
| `namiclaw CDP 启动超时,9222 未就绪` | ①`NAMICLAW_EXE` 路径对不对(Mac 要指到 `.app/Contents/MacOS/` 内可执行文件);②手动双击客户端能否打开;③端口被占换 `CDP_PORT` |
| `未配置 NAMICLAW_EXE` | 这台机没填被测客户端路径却派了 gui 用例:填 `NAMICLAW_EXE`,或别把 gui 用例派到这台 |
| 复位后提示**会话已过期/登录弹窗** | 在执行机手动打开客户端**重新登录**一次,再继续(见 §7.3) |
| 一批 gui 用例全 fail 且 `fail_kind=selector` | 环境阻塞不是功能问题:多为掉登录/首页没停稳/CDP 未就绪。逐条看 `reason`;必要时关掉手动开的客户端让 runner 冷启动 |
| `claude 执行超时(>...ms)` | 用例太重或卡住:调大 `.env` 的 `CLAUDE_TIMEOUT_MS`;或给该用例补结构化 `script` 走确定性执行更快更稳 |
| 某 gui 元素定位不到(`selector` 失败) | 选择器库没覆盖该元素:按 `gui-mcp/README.md` 用 `gui_probe` 探候选、补进 `selectors.json` 后 `git pull` |
| Mac 上 OS 级 ESC 自愈不生效 | 给终端/Node 授予**系统设置 → 隐私与安全性 → 辅助功能**权限(否则 `osascript` 静默失败,仅影响关系统窗那一招) |
| 日志一片正常但结果没回写 | 看是不是网络抖动;runner 会继续下一轮,通常自愈。持续异常查 `BASE_URL`/token |

## 11. 安全与边界

- **用例内容经 stdin 传给 claude,不进命令行**:能编辑用例的成员本可借元字符在执行机上注入命令,已通过 stdin 传参堵死(gui/e2e 更是**一个内置工具都不给**,只放 `mcp__gui__*`;api/cli 只给 Bash 并禁掉一切翻代码/联网/改文件的工具)。
- **MCP 隔离**:runner 调 claude 时 `--strict-mcp-config` 只加载本目录 gui server,屏蔽你机器上的全局 MCP(否则会连带拉起一堆无关 server 拖慢甚至卡死)。
- **只测被测客户端本身**:执行器被约束**不去翻本地代码仓库 / 平台源码**(哪怕 runner 恰好跑在某个代码目录里)。
- **凭证只在本机**:`.env`(含 token)、`node_modules`、`evidence/` 已被 `.gitignore` 忽略,别提交、别外发。

## 附 A:结构化 script 长什么样(理解确定性执行)

结构化 `script` 是**平台在用例上维护**的步骤数组,下发时由后端塞进 `payload.script`(见 `app/api/exec_queue.py::_payload_of`)。
runner 拿到后由 `step-executor.mjs`(gui/e2e)/ `api-executor.mjs`(api)**逐步确定性执行**。你作为执行机操作员通常不用写它,
但看懂它能帮你判断一条 fail 到底卡在哪一步。

**gui/e2e 用例的 script**(每步 `{action, target?, args?, desc?}`;`target` 用 `key`(语义选择器,推荐)或 `selector`(原始 CSS 兜底)):

```jsonc
[
  { "action": "connect", "desc": "连 CDP 并下钻业务 iframe" },
  { "action": "click",   "target": { "key": "navTasks" }, "desc": "点主导航『任务』" },
  { "action": "fill",    "target": { "key": "chatInput" }, "args": { "text": "你好" }, "desc": "输入" },
  { "action": "wait_response", "args": { "timeout_ms": 60000 }, "desc": "等 AI 回复完成" },
  { "action": "assert_text",   "target": { "key": "navItemActive" },
    "args": { "expected": "任务", "contains": true }, "desc": "断言当前项是任务" },
  { "action": "assert_visible", "target": { "key": "homepageTitle" }, "desc": "断言首页标题可见" },
  { "action": "assert_absent",  "target": { "selector": ".loading-mask" }, "desc": "断言遮罩已消失" },
  { "action": "judge", "args": { "question": "AI 回复是否答到了用户的问题?" }, "desc": "主观判定" },
  { "action": "screenshot", "args": { "path": "evidence/final.png" }, "desc": "存证" }
]
```

- 支持动作:`connect / click / hover / fill / wait_for / wait_response / get_text / screenshot / goto`;
  断言:`assert_text`(`args.expected` + `contains` 包含 / 省略则等于,可加 `negate` 取反)、`assert_visible`、`assert_absent`(应消失);
  `judge`(主观判定,把前面 `get_text`/`screenshot` 抓到的上下文喂给 claude 只判这一步)。
- 出现执行器**不认识的动作** → 整条降级回 Claude 兜底(日志打 `script 需降级`)。
- 判定:任一 `assert_*` / `judge` 失败 → 整条 fail。`assert_text`/`assert_absent`/`judge` 判不过归 **`business`**(真功能问题);
  定位不到元素、操作抛错、超时归 **`selector`**(环境阻塞)。

**api 用例的 script**:由 `api-executor.mjs` 执行,用例快照会带一份 `api_env`(base_url / auth),
用"下发那一刻的配置快照"避免执行时配置漂移。同样"有 script 走确定性、无则 Claude + Bash 兜底"。

> 一句话:**gui/e2e/api 尽量在平台上给用例配好结构化 script**——比让大模型看一眼判定更快、更稳、可复现,且失败点精确到步。
