# ⚠️ 这份代码已并入 qalab 平台后端，无需再次并入

本目录（`tools/qalab-runner/platform/`）曾是 runner 交接时附带的**平台侧参考代码**。
它已按本仓库架构改写并并入实际后端（鉴权、落点、枚举、schema 同步），
原始的两个裸参考文件（`models/exec_queue.py`、`routers/exec_queue.py`）**已删除**——
因为其 `enqueue` 是无鉴权裸接口、`report` 无归属校验，与实际并入版本不一致，留着会误导安全审查与后来人。

**实际生效的平台侧代码在这里：**

| 功能 | 实际生效位置 |
|---|---|
| 模型 | `backend/app/models/exec_queue.py` |
| 路由 | `backend/app/api/exec_queue.py` |
| — | `backend/app/schemas/exec_queue.py`（新增，Pydantic 入参）|
| — | `backend/app/core/deps.py::require_runner`（runner 鉴权依赖）|
| — | `backend/app/core/enums.py`（新增 ExecKind / ExecStatus）|
| — | `backend/sql/schema.sql`（新增 exec_run 表 + test_case.exec_kind 列）|

与参考实现的主要差异（按本仓库约定改写 + 修安全隐患）：
- 鉴权用 `settings.RUNNER_TOKEN`（config.py）而非 `os.environ`，走 `HTTPBearer` 依赖。
- `enqueue` 接入用户 JWT + `assert_project_role(member/admin)`，入参用 `checklist_item_ids` 并校验归属
  （参考件是**无鉴权裸接口**，已修）。
- `claim`/`report` 增加 **runner 归属校验**：只能认领/回写派给自己（`?runner=<RUNNER_ID>`）的执行项，
  避免多台 runner 共用 token 时互相认领/回写串扰（参考件缺此校验，已修）。
- **回写落点**：`PATCH` 除更新 `exec_run` 外，同步 `checklist_item.exec_status`（pass→passed / fail→failed），
  复用现有清单展示 / checklist-summary 统计 / 失败转遗留问题等全部下游能力。
- `status/kind` 用枚举；表名 `exec_run`；`payload` 用 Text 存 JSON（兼容 MySQL 5.6）。

**你要做的只是配置 + 部署 runner**，见 `../README.md` 与 `../HANDOFF.md`。
