# 对话测评 runner 本地部署使用手册（平台模式）

面向：在本机跑「对话测评执行器」，从测试管理平台拉对话测评任务、驱动被测客户端（纳米Work / WorkBuddy）执行、把结果回写平台。

> 与同目录旧 `部署手册.md` 的区别：旧手册是**飞书表格模式**（从飞书读 query、回填飞书，`ai-eval.js run`）；本手册是**平台模式**（从测试管理平台拉任务、回写平台，`ai-eval.js platform`）——当前主用形态。

---

## 一、整体形态

```
测试管理平台(后端 :8000)  ──下发对话测评任务──▶  本机 runner(ai-eval platform 常驻轮询)
        ▲                                              │
        │                                    CDP 驱动被测客户端
        └──────回写(答案/耗时/算力豆/分享链接/raw_message)──┘
                                             ├─ 纳米Work  (CDP 9222, iframe 架构)
                                             └─ WorkBuddy (CDP 9335, 单页 Electron)
```

- runner **常驻轮询**平台，按 `target_engine` 把任务分发给纳米或 WorkBuddy 执行器。
- WorkBuddy 独立端口 9335，与纳米 9222 不冲突；但纳米功能测试 run.sh 与对话测评 run-eval.sh 抢同一 Namiwork+9222，互相 pkill，不能同时跑。
- **执行机平台限制**：WorkBuddy 是 mac 客户端 + 附件走 macOS 剪贴板/AppKit，**WorkBuddy 目前仅 Mac 真机验证过**；纳米 Mac/Windows 都可。

## 二、准备清单

| # | 需要的东西 | 说明 |
|---|---|---|
| 1 | Node.js 18+ | https://nodejs.org 下载 LTS |
| 2 | 平台地址 + RUNNER_TOKEN | 须与平台后端 `.env` 的 `RUNNER_TOKEN` 完全一致 |
| 3 | 被测客户端 | 纳米Work（`/Applications/Namiwork.app`）和/或 WorkBuddy（`/Applications/WorkBuddy.app`） |
| 4 | 被测账号登录态 | 纳米：录登录态（第六节）；WorkBuddy：客户端内已登录即可 |
| 5 | （Mac，WorkBuddy 需要）辅助功能权限 | 系统设置→隐私与安全性→辅助功能→打开终端(iTerm/Terminal)，附件粘贴前台化用 |

## 三、安装（只需一次）

```bash
cd tools/qalab-runner/eval
npm install                        # 装 playwright 等依赖(首次约 150MB)
npx playwright install chromium    # 若 CDP 连接报缺内核再执行
```

依赖只装在 `eval/`（node_modules 不共享，worktree 跑不了，只能在主检出装）。

---

## 四、配置 .env（一处配置，两执行器通用）

配置在**上级** `tools/qalab-runner/.env`（不是 eval 里）：

```bash
cd tools/qalab-runner
cp .env.example .env
```

关键项：

```
BASE_URL=http://<平台后端IP>:8000      # 只填站点根,/api 由 runner 自己拼
RUNNER_TOKEN=<与平台后端 .env 完全一致>
RUNNER_ID=mac-01                        # 本机执行机标识,平台按此派发;多台各用不同 id、共用同一 token
POLL_MS=5000                            # 常驻轮询间隔(ms)

# 纳米Work(执行纳米用例的机器需要;留空=这台不跑纳米)
NAMICLAW_EXE=/Applications/Namiwork.app/Contents/MacOS/Namiwork
CDP_PORT=9222
```

WorkBuddy 无需在 .env 配路径（`workbuddy-pool` 默认 `/Applications/WorkBuddy.app/Contents/MacOS/Electron` + 环境变量 `WORKBUDDY_REMOTE_DEBUGGING_PORT=9335` 自动拉起）；装在别处用 `WORKBUDDY_EXE` 覆盖。

> `.env` 只在本机、不提交。功能测试 runner(run.sh) 与对话测评 runner(run-eval.sh) 共用这一份。

---

## 五、启动 runner（平台模式）

在 `tools/qalab-runner/` 下：

```bash
./run-eval.sh          # Mac/Linux
run-eval.cmd           # Windows
```

脚本行为：
- `cd eval && node bin/ai-eval.js platform`，读上级 `.env`，常驻轮询平台。
- **自更新**：平台推新 runner 包时执行器退出码 75，脚本循环重启进新代码。
- 调试：`./run-eval.sh --once`（只一轮）、`--limit 3`（限量）。

启动后日志打印「拉到 N 条待执行」，按引擎分发。带附件会话先下载附件再执行。

## 六、纳米Work 登录态录制（每账号一次）

WorkBuddy 在客户端内登录即可，跳过本节。

```bash
cd tools/qalab-runner/eval
node bin/ai-eval.js login -a <账号名>          # 有桌面:弹浏览器登录 work.n.cn,登录后回命令行按回车
node bin/ai-eval.js login -a <账号名> --cdp    # 无桌面/远程:先带调试端口起 Chrome 登录再跑
```

登录态存 `eval/accounts/<账号名>.json`；`config/default.config.js` 的 `accounts` 要列出对应账号名。过期重录即可。

---

## 七、WorkBuddy 专项（附件 + raw_message）

WorkBuddy 走 CDP 9335，由 `workbuddy-pool` 自动带 `WORKBUDDY_REMOTE_DEBUGGING_PORT=9335` 拉起并 attach。三项能力（均真机坐实）：

- **对话执行**：新建任务→输入→选模型档→发送→等完成→抓答案/耗时/来源。
- **带附件会话**：附件走 Electron 原生文件对话框(`setInputFiles` 不适用)。方案 = 附件下本地→写系统剪贴板(mac `public.file-url`/win `CF_HDROP`)→聚焦编辑器→CDP 发 `Meta+V`(mac)/`Control+V`(win)→等 `[data-content-block-meta-type=file]` 就绪→再输 query→发送。**Mac 需辅助功能权限**。
- **raw_message**：抓「更多操作→复制 message」完整结构化 JSON(思维链/工具调用/traceId/modelId)，回写 `eval_run.raw_message`，供综合评价深度归因。

手动带调试端口起 WorkBuddy(排查用)：
```bash
WORKBUDDY_REMOTE_DEBUGGING_PORT=9335 /Applications/WorkBuddy.app/Contents/MacOS/Electron
curl -s http://127.0.0.1:9335/json/version    # 验证端口就绪
```

## 八、排查

| 现象 | 处理 |
|---|---|
| 启动报 BASE_URL/RUNNER_TOKEN 缺失 | 检查上级 `.env` 填全、runner 在 `tools/qalab-runner/` 下启动 |
| 「平台无待执行任务」 | 正常，平台还没下发；到平台建测评任务并执行 |
| 拉到任务但纳米执行失败 | 确认 `NAMICLAW_EXE` 路径、9222 未占、账号登录态未过期 |
| WorkBuddy 连不上 | `curl http://127.0.0.1:9335/json/version`；客户端是否已装/已登录 |
| WorkBuddy 附件没挂上 | Mac 辅助功能权限是否给了终端；日志看 `附件粘贴后未就绪`；Windows 版未真机验证 |
| raw_message 为空 | 仅 WorkBuddy 抓得到(纳米走 trace)；抓不到不阻断,属正常降级 |
| 改了 runner 代码不生效 | 服务器 `git pull` 后 Ctrl-C 重启 run-eval |
| 纳米功能测试与对话测评想同跑 | 不行,抢 9222;WorkBuddy(9335) 可与纳米同跑 |

## 十、部署到新机器

打包整个 `tools/qalab-runner/`（含 `eval/`），**排除**：`.env`（含 token，各机独立）、`eval/accounts/`（登录态，各账号独立录）、`eval/node_modules/`、`eval/output/`（生成）。

新机：装 Node → `cd eval && npm install` → 填上级 `.env` → 录纳米账号(如需)/WorkBuddy 客户端登录 → `./run-eval.sh`。
