# AI 对话测评自动化工具 — 部署手册

面向零代码基础的测评同事。按本手册从头做一遍，即可在自己电脑上跑批量测评并自动回填飞书表格。

---

## 一、这个工具做什么

自动从飞书表格读取一批 query（含附件）→ 逐条发到测评平台（work.n.cn / 纳米Work）→ 等回答结束 →
把【对话分享链接、产物分享链接、耗时、算力豆消耗、正文】自动回填到飞书表格对应行。

一条跑完立即回填一条；多个账号可并行，同一账号内也可并行多条任务（发送按顺序、逐条确认已开始执行）。

---

## 二、准备清单（开始前先备齐）

| # | 需要准备的东西 | 从哪来 / 谁提供 |
|---|---|---|
| 1 | 一台 Windows 10/11 电脑，能上网 | —— |
| 2 | Node.js 18 或更高 | https://nodejs.org/zh-cn/ 下载 LTS 版，一路默认安装 |
| 3 | 测评平台账号（work.n.cn） | 你自己的测评账号，能正常登录发消息 |
| 4 | 飞书「自建应用」的 App ID 和 App Secret | 见 [第四节]，找负责人要或自己创建 |
| 5 | 测评用例飞书电子表格的链接 | 找负责人要统一那张表 |
| 6 | 该表格已授权给上面的飞书应用 | 见 [第四节·3] |

> 术语说明：**登录态** = 把你在浏览器里登录好的状态保存成一个本地文件，工具用它免密操作平台，不会保存你的密码。

## 三、安装（只需一次）

1. 把整个 `ai-eval-cli` 文件夹拷到电脑上（建议放在没有中文、没有空格的路径，如 `D:\ai-eval-cli`）。
2. 双击 **`安装.bat`**。它会自动：检查 Node.js → 安装依赖 → 下载浏览器内核 → 生成 `.env` 配置文件。
3. 看到「安装完成！」即可。首次安装需联网下载约 150MB，请耐心等待。

> 如果提示「未检测到 Node.js」：先按第二节装好 Node.js，再重新双击 `安装.bat`。

---

## 四、飞书配置（核心，务必按顺序做）

### 1. 创建 / 获取飞书自建应用

1. 打开飞书开放平台 https://open.feishu.cn/ → 右上角「开发者后台」。
2. 「创建企业自建应用」，填名称（如“测评自动化”）、图标，创建。
3. 进入应用 →「凭证与基础信息」页，能看到：
   - **App ID**（形如 `cli_axxxxxxxxxxxx`）
   - **App Secret**（一串字符，点“查看/复制”）

   这两个就是准备清单里的第 4 项。

### 2. 开通权限

应用后台 →「权限管理」，搜索并开通以下权限（用于读写电子表格、下载附件）：

- `sheets:spreadsheet`（电子表格读写）— 或分别开通 `查看、评论、编辑和管理电子表格`
- `drive:drive`（云空间文件，附件下载需要）
- 如表格在 **知识库(wiki)** 里，再加 `wiki:wiki:readonly`（读取知识库节点）

开通后点「创建版本 / 发布」，让权限生效（企业内应用可能需管理员审批）。

### 3. 把表格授权给应用（最容易漏！）

光有权限还不够，必须把**那张具体的表格**共享给应用：

- 打开测评飞书表格 → 右上角「···」或「分享」→ 添加协作者 →
  搜索你的**应用名称**（自建应用可作为协作者添加）→ 给「可编辑」权限。
- 若找不到应用作为协作者，则确认第 2 步权限已发布，或联系飞书管理员协助授权。

### 4. 把凭证填进工具

用**记事本**打开工具目录下的 **`.env`** 文件，填入第 1 步拿到的两个值，保存：

```
FEISHU_APP_ID=cli_你的AppID
FEISHU_APP_SECRET=你的AppSecret
```

> `.env` 只存在你本机、不会外传。切勿把 App Secret 发群里或提交到代码仓库；一旦泄露，去应用后台「重置」即可。

## 五、测评飞书表格的格式要求

工具默认按下面的列布局读写（可在 `config\default.config.js` 调整）：

| 列 | 用途 | 读/写 |
|---|---|---|
| A | **query**（要测评的问题） | 读 |
| B | **附件**（可空；单元格内插入的图片/文件，或一个附件下载链接） | 读 |
| C | 对话分享链接 | 工具写回 |
| D | 产物分享链接（无产物则空） | 工具写回 |
| E | 对话耗时 | 工具写回 |
| F | 算力豆消耗 | 工具写回 |
| G | （留空，工具不碰） | —— |
| H | 正文内容（AI 回答全文） | 工具写回 |

要点：
- 第 1 行放表头，用例从**第 2 行**开始（对应配置 `startRow: 2`）。
- 默认读到第 200 行（`endRow: 200`），可调大。
- A 列为空的行会被自动跳过。
- 结果按**真实行号**回填，不会因为并发complet( 完成顺序不同而错行。

## 六、修改配置文件

用记事本打开 **`config\default.config.js`**，通常只需改这几处：

1. **表格链接** `feishu.url`：换成你们的测评表格链接（支持 `/sheets/...` 或 `/wiki/...` 两种）。
2. **账号列表** `accounts`：改成你自己的账号名（要和第七节录制时输入的名字一致）：
   ```js
   accounts: [
     { name: 'zhangsan', storageState: './accounts/zhangsan.json' }
     // 有多个账号就并列多行，多个账号会并行跑、互不干扰
   ],
   ```
3. **并发账号数** `browser.maxConcurrent`：同时并行的**账号**数量，一般保持默认即可。
4. **单账号内任务并发数** `browser.perAccountConcurrent`：同一账号同时并行执行的任务数（每个任务占一个浏览器标签页），默认 3。发送严格按顺序、逐条确认已进入“执行中”后才发下一条；发出后各任务在后台并行等待与抓取。设为 1 即退回“单账号内逐条串行”。
   - 执行过程中若平台弹确认框（反问 / 授权 / 风险提示），程序会自动点“确认 / 继续 / 允许”等按钮让任务继续；按钮文案 / 选择器可在 `platform.confirmButtonTexts`、`platform.confirmButtonSelectors`、`platform.confirmDialogSelector` 调整。
   - 若任务执行中**专家反问**（弹出选择题、需先选选项再点“提交”才继续），程序会**自动为每道题选一个选项（默认选第一个；已预选的题保持不动），全部选完点“提交”**，多轮反问会逐轮自动回答，直到任务继续跑完。这类反问在 work.n.cn 是内联卡片（`chat-question-form-card`），默认选择器已按实际页面配好（`platform.askForm*` 项），一般不用动；若平台改版导致答不上，按 `config` 里 `askFormSelector / askFormOptionSelector / askFormOptionsGroupSelector / askFormSubmitSelector` 的注释更新即可。
   - 若弹窗是普通 modal 选择题，程序同样会每题勾一个、点“提交”（`platform.choice* / submitButton*`）。
   - 后台会按 `execution.watchIntervalMs`（默认 15 秒）巡检各任务标签，打印“执行中 / …”状态；设为 0 可关闭巡检日志。

其余（platform 选择器、超时、回填列）一般不用动。若测评平台页面改版导致抓不到内容，再按注释调 `platform` 里的选择器。

## 七、录制登录态（每个账号一次）

1. 双击 **`录制账号.bat`**。
2. 按提示输入账号名（要和配置里 `accounts` 的 `name` 一致，如 `zhangsan`）。
3. 弹出的浏览器里用该账号登录 work.n.cn，登录成功、能看到对话界面后，**回到命令行窗口按回车**。
4. 成功后 `accounts\zhangsan.json` 会生成。多个账号就重复本步骤。

> 登录态会过期。若某天运行时提示找不到对话框/像是未登录，重新录制一次即可。

### 录制遇到问题？

录制需要弹出一个**可见的浏览器窗口**让你登录。绝大多数办公电脑没问题；若失败：

- **窗口一闪而过 / 报“浏览器启动崩溃”**：多为该机器无桌面会话（远程/服务方式）或安全软件拦截。改用 **CDP 模式**录制：
  1. 关掉所有 Chrome 窗口，然后用powershell启动一个带调试端口的 Chrome：
     ```
     "& "C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222 --user-data-dir="$env:TEMP\chrome-eval""
     ```
  2. 在弹出的这个 Chrome 里登录 work.n.cn。
  3. 再到程序所在路径下运行： `node bin\ai-eval.js login -a 账号名 --cdp`  按提示回车保存。账号名是刚才登录到系统的用户名
  4. **要连续录多个账号**：上一步保存成功后，程序会**自动清掉这个 Chrome 的登录态并跳回登录页**，你直接在**同一个 Chrome 窗口**登录下一个账号，再跑一次 `node bin\ai-eval.js login -a 下一个账号名 --cdp` 即可，如此重复。不用关 Chrome、不用换命令。
     - 若只想录一个、不希望被清登录态，加 `--no-clear`：`node bin\ai-eval.js login -a 账号名 --cdp --no-clear`
     - ⚠️ 之前遇到的“连续录多个账号都是上一个账号登录态”，正是因为 `--user-data-dir` 是固定目录会复用登录态——现在录完自动清除已解决；若仍异常，可手动在 Chrome 里退出账号，或关掉 Chrome、删除 `%TEMP%\chrome-eval` 目录后重开。
- **能弹窗但登录后按回车没反应**：确认焦点回到了命令行黑窗口再按回车。

## 八、运行测评

- **先验证配置**：双击 **`查看用例.bat`**，能列出表格里的用例 = 飞书连通、表格读取正常。
- **正式执行**：双击 **`运行测评.bat`**。无头运行（不弹窗口属正常），每条跑完实时回填飞书。
- 结束后：结果已在飞书表格里；本地 `output\时间戳\` 下还有 `result.json`、`summary.md` 备份。

> 复杂任务（生成网页/方案/文件）单条可能要几分钟到十几分钟；同账号内多条会并行推进，但发送是逐条确认后进行的，整批仍可能耗时较长，属正常。

## 九、常见问题排查

| 现象 | 处理 |
|---|---|
| 双击 bat 一闪而过 | 右键 bat →「以管理员身份运行」，或在窗口里看报错信息；确认路径无中文/空格 |
| 提示未检测到 Node.js | 装 Node.js 18+ 后重跑 `安装.bat` |
| `飞书认证失败` / 读表格报错 | 检查 `.env` 的 App ID/Secret；确认权限已发布、且表格已共享给应用（第四节 2、3） |
| 找不到对话输入框 / 像未登录 | 登录态过期，重跑 `录制账号.bat` |
| 浏览器启动失败 | 执行 `npx playwright install chromium` 重装内核；或把 `config` 里 `browser.channel` 改成 `chrome` |
| 附件没识别 | 确认附件在 B 列，是图片/文件或 http 链接；把该单元格情况反馈给维护者 |
| D 列（产物链接）偶尔空 | 该用例可能确无产物；若确有产物仍空，反馈维护者 |
| 某条超过 3 小时没结束 | 极端情况，调大 `config` 里 `execution.responseTimeout` |
| 正文/耗时列出现 `[未完成:xxx]` 或为空 | 该条任务未真正跑完（`timeout`=等满上限 / `stall`=长时间卡住无进展 / `nostart`=没启动起来）。程序**不再把"思考中…"中间态当成功回填**；这类多是任务卡在需人工介入处，可到平台手动查看该对话，或调大 `execution.stallTimeout` / `responseTimeout` 后重跑该条 |

## 十、打包发给同事时应包含的文件

把整个文件夹打包（zip）发出去，**必须包含**：

```
ai-eval-cli\
├── 安装.bat              ← 双击安装
├── 录制账号.bat          ← 录制登录态（单账号）
├── 批量录制登录态.bat    ← 批量录制登录态（见第十一节，需飞书台账+Python/ddddocr）
├── 运行测评.bat          ← 跑测评
├── 查看用例.bat          ← 验证配置
├── 部署手册.md           ← 本文件
├── bin\  src\  config\   ← 程序与配置模板
├── tools\                ← 验证码识别脚本 solve_captcha.py（批量录制用）
├── package.json  package-lock.json
└── .env.example          ← 凭证模板（同事安装后会自动复制成 .env）
```

**不要**打包进去（属个人私密 / 可再生）：
```
.env            ← 含你的密钥
accounts\       ← 含你的登录态 cookie
node_modules\   ← 安装时会自动生成
output\         ← 运行结果
```
（这些已在 `.gitignore` 里；用压缩软件打包时手动排除即可。）

> 每位同事拿到后，各自：装 Node → 双击安装 → 填自己的 `.env` → 录自己的账号 → 运行。凭证和登录态每人独立，不要共用。

## 十一、批量录制账号登录态（管理员 / 批量场景）

当需要**一次性录制大量账号**（如几十上百个测评小号）的登录态时，用这个自动化流程，
无需人工一个个登录：从飞书「账号台账表」读取待录账号，逐个用**账号密码**自动登录
`work.n.cn`、保存登录态、并回填台账。风控偶发的**图形验证码由程序离线自动识别**，全程无人值守。

> 与第七节的区别：第七节是「一个账号、人工登录一次」；本节是「一张台账、批量账号密码登录、自动识别验证码、自动回填」。

### 1. 账号台账表格式

在飞书里准备一张**账号台账表**（与测评用例表是两张不同的表），按列存放账号信息：

| 列 | 用途 | 读/写 |
|---|---|---|
| D | **qid**（账号唯一标识，登录态文件名与回填都用它） | 读 |
| E | **账号**（登录手机号，作为用户名） | 读 |
| F | **密码** | 读 |
| C | 已录 qid（成功后写入实际登录得到的 qid） | 工具写回 |
| G | 是否已录制登录态（`否`/空=待录；成功后写 `是`） | 工具读+写 |

- 列位置可在 `config\default.config.js` 的 `accountRecording` 节调整（`qidCol/phoneCol/passwordCol/statusCol/recordedQidCol`）。
- 表头在第 1 行，账号从第 2 行起。**G 列 = `是` 的行会被自动跳过**（已录）。

### 2. 一次性准备

1. **飞书凭证**：`.env` 里的 `FEISHU_APP_ID / FEISHU_APP_SECRET`（同第四节），并把**台账表**也共享给该飞书应用（可编辑）。
2. **台账表链接**：填到 `config\default.config.js` → `accountRecording.url`。
3. **验证码识别库**（Python）：装好 Python，然后：
   ```
   pip install ddddocr
   pip install onnxruntime==1.20.0
   ```
   > ⚠️ 必须指定 `onnxruntime==1.20.0`。最新版 onnxruntime 在部分机器会「DLL 初始化失败」。
   > 若 `python` 不在 PATH，把解释器完整路径填到 `accountRecording.pythonPath`。
4. **浏览器**：无需手动开。程序会在需要时自动带调试端口拉起一个**独立 Chrome**（专用用户数据目录，不影响你日常的 Chrome）。如未装 Chrome 或路径特殊，填 `accountRecording.chromePath`。

### 3. 运行

**双击 `批量录制登录态.bat`**，按提示选：

- `[1] 试跑 3 个`：先验证链路（**首次务必先跑这个**）。
- `[2] 全量录制`：多轮自动重试（`--passes 3`）。
- `[3] 全量·慢速`：账号间隔 30 秒，尽量绕开风控验证码，最稳但慢。

或用命令行（更灵活）：
```
node bin\record-accounts.js               # 全量一轮（从飞书自取清单，跳过已录）
node bin\record-accounts.js --limit 3     # 只录前 3 个未录的（试跑）
node bin\record-accounts.js --passes 3    # 整批重跑 3 轮（捡回验证码卡壳的）
node bin\record-accounts.js --delay 30000 # 账号间隔 30 秒（慢速，绕风控）
node bin\record-accounts.js --from 100    # 只处理台账行号 ≥100 的
```

结果：登录态存到 `accounts\<qid>.json`；台账对应行回填 `C=qid、G=是`；明细见 `output\_record_result.json`。

### 4. 关于验证码与风控（重要）

- 账号密码登录**大多数情况直接成功、不弹验证码**；只有**短时间内连续登录多个**时，平台风控才会弹图形验证码。
- 风控会随时间/空闲**自动衰减**。所以策略是：**多轮重跑 + 拉大间隔**——第一轮没过验证码的账号，
  下一轮（或慢速模式）风控降下来后往往免验证码直接过。程序已内置多轮与冷却，**你只管重跑**。
- 整个流程**幂等**：已录（台账=`是` 或本地已有 `accounts\<qid>.json`）的会自动跳过，**放心反复跑**直到全绿。

### 5. 常见问题

| 现象 | 处理 |
|---|---|
| 提示 `未找到可用的 Python` | 装 Python 并加入 PATH，或填 `accountRecording.pythonPath` 完整路径 |
| 提示 `ddddocr 加载失败` / onnxruntime DLL 错误 | `pip install onnxruntime==1.20.0`（降级即可） |
| 提示 `Chrome 调试端口未就绪且未找到 chrome.exe` | 装 Chrome，或填 `accountRecording.chromePath` |
| 汇总里有「仍未录」 | 多为验证码卡壳。**过一会儿再跑一次本流程**（或用慢速模式），已录会自动跳过 |
| 某账号一直 `bad_password` | 该账号密码不对，核对台账 E/F 列 |
| 飞书回填偶发失败 | 已内置 token 失效自动刷新重试；如仍失败，重跑一次即可补填（登录态不会重录） |
