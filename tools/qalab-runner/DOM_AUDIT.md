# DOM 巡检

通过选择器管理的“立即巡检”或“每日巡检设置”下发到所选设备的 Runner。

- `dom-audit-pages.json` 声明导航步骤、就绪锚点、采集根节点和关闭按钮。当前包含主页面、任务/技能/项目详情、分类、项目创建弹窗和设置子页。列表只打开一个现有条目检查模板，不遍历每条业务记录。
- 只执行清单中的点击/悬停导航，不执行保存、发布、删除、发送消息或设置开关。缺失入口记为未覆盖；不会据此判废弃。
- 唯一 testid 优先，其次现场验证的 CSS；无法生成可靠 CSS 时验证 XPath。XPath 不跨 Shadow DOM，无法验证的节点如实计入无有效定位。
- 重复列表的同类控件归并为集合候选（`src: audit_collection`），说明标明“列表集合，多个”。使用集合执行操作时必须再通过 `has_text`、`within` 或 `nth` 指定目标；不会默认点击第一条。
- CSS/XPath/集合按页面隔离，公共稳定 testid 可复用。页分组重命名后通过巡检页面记录保持身份；重复巡检不重复新增相同定位。
- 扫描数是元素出现次数，归并后是本轮命中的唯一注册项。报告另列列表集合数、定位类型、无有效定位、冲突和逐页覆盖。
- 巡检管理的条目在其页面连续两次完整覆盖且缺失时自动标废弃；确认属于列表集合的旧自动生成逐项 XPath 会标废弃，并在本次记录中写明替代集合。人工维护的候选链和并发编辑不会被覆盖。
- 不读取输入框值作为 DOM 说明；不采集截图。采集可见可交互控件、测试标识与可用于断言的标题标签，过滤仅继承鼠标样式的装饰节点。

运行需要本版本 Runner；旧 Runner 不具备集合及深层清单处理能力。页面清单需随应用版本维护，隐藏功能、未登录内容、未配置入口及虚拟列表尚未渲染的分支不会被宣称已覆盖。
