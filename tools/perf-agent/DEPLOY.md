# 性能测试执行机 · 部署说明

在**被测机器**（装了纳米 Work 的 Windows）上运行本工具，把该机的性能采集接入测试管理平台。
**不需要平台源码、不需要代码权限** —— 只是一个下载即用的小程序。

---

## 一次性准备（约 5 分钟）

### 1. 装 Node.js
到 https://nodejs.org 下载 **LTS 版**（v18 以上）装好。装完在命令行 `node -v` 能出版本号即可。

### 2. 解压本包
解压到任意目录，例如 `D:\perf-agent`。目录里应有 `perf-agent.mjs`、`nami-perfdog.mjs`、`run.cmd`、`.env.example` 等。

### 3. 在平台注册执行机、拿 token
1. 浏览器登录测试管理平台。
2. 进 **「我的工作台 → 我的设备」**，点「注册设备」：
   - runner_id：给这台机起个稳定标识，如 `win-01`
   - 名称：如「张三的测试机」
3. 注册后会返回一串 **token（只显示这一次，复制好）**。

### 4. 配置
把 `.env.example` 复制一份改名为 `.env`，用记事本填 4 项：
```
BASE_URL=http://<平台地址>:8000      # 平台后端地址，问管理员
RUNNER_TOKEN=<上一步复制的 token>
RUNNER_ID=win-01                     # 与注册时填的一致
PERFDOG_DIR=                         # 留空即可（默认用本目录）
```

## 日常使用

### 启动执行机
双击 **`run.cmd`**（或命令行 `node perf-agent.mjs`）。看到
`perf-agent 轮询启动 · runner=win-01` 就成功了，**保持这个窗口开着**。

### 下发采集（长监控，可无人值守）
平台 **「性能测试 → 任务下发」**：
1. 新建 / 选一个报告集
2. 场景选「长监控」，时长填 `40s`（或 `30m`/`12h`），对象标签填被测版本号
3. 点「下发」→ 自动进入实时监控页，能看到 CPU/内存实时曲线
4. 采集结束自动进「性能报告」，按报告集看对比

### 交互场景（冷启动 / 对话 / 热启动等）
这些需要人工操作，不能无人值守。在本机：
1. 双击 `纳米性能测试.bat` 选场景，按屏幕提示操作
2. 采完运行 `node perf-agent.mjs upload` 直传平台
3. 平台「性能报告」即可看到

## 采到"真实数据"的前提（重要）

- **被测应用必须在本机运行**，且采集期间**真实操作它**（切会话、发消息）——否则 CPU/内存是平线（应用空转）。
- 采集对象默认是纳米 Work 桌面端进程（`namiclaw.exe`）。测**竞品**时下发填「竞品进程」，或本地 `--proc 进程名.exe`。
- 要 **FPS / 启动分段耗时**：先彻底退出纳米 Work（含托盘），再带调试端口启动：
  ```
  & "安装路径\Namiwork.exe" --remote-debugging-port=9222
  ```
  不带也能测，只是没有 FPS。

## 常见问题

| 现象 | 原因 / 解决 |
|---|---|
| 任务一直 `pending` | 执行机 `run.cmd` 没开着，或 RUNNER_ID 与下发选的执行机不一致 |
| CPU/内存全是 0 | 被测应用没在跑，或进程名不对（默认 `namiclaw.exe`，竞品用 `--proc`） |
| FPS 一直空 | 没带 `--remote-debugging-port=9222` 启动应用 |
| 无效的 runner 令牌 | `.env` 的 RUNNER_TOKEN 填错，或该设备被删；重新到「我的设备」拿 |
