# 可独立回归的数据准备

生成前为每个场景记录：数据策略、对象条件、就绪证据、无合适对象时的步骤、对象标识来源、业务断言和恢复方式。实际操作与最终脚本一致；变量值来自本次真实观察。

## 选择策略

- **优先复用**：回答赞踩、打开详情、复制分享等，不以新建为验收目标。优先使用当前账号可操作的既有测试数据。回答应已完成、有相应操作按钮；赞踩优先选择未评价的回答，操作后恢复。按列表顺序选择首个符合条件的对象是明确的测试取样规则，须限定容器、记录对象标识，不是用 nth 隐藏歧义。若要尝试多个会话，展开有限数量的明确步骤并记录每次条件，不能无限扫描或隐式交给 AI 自行执行。
- **必须构造**：精确搜索、创建后的标题变化、目录结构、编辑版本等需要特定初始条件。脚本完成创建/保存并确认持久化，再捕获对象标识。必要前置不得只写自然语言备注。每次创建使用唯一标记；无写权限时阻塞，不绕过权限或改动他人数据。
- **动态选择**：热门榜单、商店等使用当前真实加载条目，捕获该条目的 ID/名称，再核对详情或选中对象的一致性。不能把首次看到的榜单名称固定进回归脚本。

只有数据加载成功且确认没有合适对象，才走创建分支。接口失败、登录失效、加载中、容器消失、定位冲突不是空列表。不要创建数据掩盖这些错误。测试空态本身时保持空态，不自动填充。

## script-flow-v1（平台与执行设备均需支持）

通过 `/api/verified-imports/capabilities` 检查 `replay_protocols` 包含 `script-flow-v1`。Windows/macOS 客户端在导入前检查；生成电脑不需要安装 Runner。旧平台保留原始观察包待升级；不删条件、不改投环境。旧 Runner 不能认领条件脚本，平台下发流程保持原样。

步骤仍是平铺数组，必须以以下步骤开始：

```json
{"action":"flow_start","args":{"version":1},"desc":"按当前账号准备测试对象"}
```

支持的能力：

| 字段/动作 | 格式与行为 |
|---|---|
| `set_var` | `args:{name:"created",value:false}`；或 `args:{name:"test_name",generate:"unique",prefix:"QA-feedback-"}`。值为标量，unique 产生本次唯一值，报告保留实值。 |
| `probe` | `target` 为符合条件的唯一候选；`args:{ready:{selector:"实际加载完成标记"},timeout_ms:5000,settle_ms:500,save_as:"found"}`。ready 必须表示数据加载成功，不能只是始终存在的页面外壳。有效目标稳定不存在才记录 false；失联、歧义、容器缺失报阻塞。 |
| `when` | 步骤顶层 `{var:"found",equals:false}`；或 `{var:"object_id",is_set:true}`。只执行符合条件的步骤。未赋值不能当 false；引用之前声明的变量。 |
| `get_text` | `args:{save_as:"selected_name"}`，保存本次文本。 |
| `get_attribute` | `args:{attribute_name:"data-id",save_as:"message_id"}`；读取实际 DOM 的 data-/aria- 属性或 id/title/href/src/value，缺属性报错。 |
| 变量引用 | 整个数据值写 `{"$var":"selected_name"}`。支持 args.text/expected/checked/values、target.has_text、target.attribute.value、set_var.value；不进行字符串拼接，不向 selector/frame/代码插值。 |
| 属性限定 | `target:{selector:"实际消息容器",attribute:{name:"data-id",value:{"$var":"message_id"}}}`；可放入 within，执行时仍要求唯一。 |
| `phase` | 可标记 setup/test；所有 cleanup 步骤连续放在最后。业务失败后仍尝试收尾，收尾错误另行保留，不能覆盖原始失败。只清理本次创建的对象或恢复本次修改，不删除复用数据。 |

`args.expected_from` 继续可用于 `assert_text`。变量作用域仅限本次用例，不跨用例、账号或设备传递。某分支未赋值而后续读取时会阻塞；共享变量可先初始化，或在两个分支各自捕获。

## “回答赞踩”的编写顺序

1. 进入当前账号会话列表，确认加载成功，选择一条符合条件的既有会话。
2. 确认回答完成，探测是否有支持赞踩且未评价的回答，捕获其稳定消息标识。
3. 没有合适回答时才新建测试会话、发送最小测试内容、等待真实回复完成、捕获新消息标识。建立回复基线必须在提交动作前，不能把历史回复当成本次完成。
4. 每次点击与断言限定到该消息；验证赞、取消赞、踩及互斥状态，不验证固定历史标题或固定回答原文。
5. 恢复该消息原有评价状态。只对本次创建且可明确识别的测试数据执行已授权清理。

上述是流程，不是可直接执行的 DOM 模板。必须根据实测应用获取选择器和就绪标记，再用真实条件分别实测复用/构造分支；一个分支通过不能证明另一分支通过。

## 入口与断言

- 根据当前页面观察编写入口。若需要兼容两种已确认布局，用 probe + when 显式分支，例如模板已展示直接选；未展示且旧入口存在才打开。未知页面不能一路跳过直到“通过”。
- 需求明确规定的名称、内容和顺序仍严格断言。动态捕获只用于核对身份/关联关系，不能读取实际值后原样与自己比较。
- 自动生成的技能/文件以本次对象 ID、路径或生成响应关联。先确认生成成功与可操作状态，再验证归属和内容；pending 消失或模型说“已完成”不代表实际完成。
- 失败有界停止，区分准备失败与业务断言失败，保留证据，不无限重建、重试或降低预期。

## 观察报告与导入

条件脚本 report 必须覆盖完整步骤序列，包含真实执行、明确跳过与收尾：

- 条件不满足：`ok:true,skipped:true,skip_reason:"condition_false"`。这里只表示分支判定完成，不是业务动作通过。
- 首个业务失败之后的未执行主流程：`ok:true,skipped:true,skip_reason:"previous_failure"`；不能填写 check 或捕获值。
- `set_var`、`get_attribute`、`probe` 记录 `value`；get_text 记录 `text`；每步仍有 observation 与 evidence_ref。
- 业务失败断言保留 `ok:false,fail_kind:"business",error,check:{actual,expected,pass:false}`。收尾按真实结果记录。收尾也失败时先解决恢复问题，不能封存为完整可回归的业务失败。
- 当次至少执行一个业务断言，否则阻塞。不要把未执行分支写为测试通过。HTML 报告说明实际走了哪条数据路径、创建/复用了哪个对象、未覆盖分支和恢复结果。

修改条件、目标或预期会改变脚本指纹；修改后重做受影响完整实测，旧记录不能证明新脚本。已导入的旧用例不会因更新 skill 自动变成新脚本，须单独修订和复验。
