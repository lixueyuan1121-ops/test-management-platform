# QA Lab：Codex 实测、用例转换与导入

**Codex 是首次测试的执行者，skill 是约束和中转，Runner 是平台后续回归的执行通道。** 支持在 A 电脑用 Codex 实测并导入，在 B 电脑登录平台选择执行设备回归。不得因 A 电脑没有 Runner、设备 token、Runner 目录或本地注册表而拒绝使用技能或要求安装。

## 范围与连接

- 输入不足时读取 [输入卡片](references/intake.md)，只询问缺少的需求和应用地址。用户已有回答继续沿用；异步 accepted 不是回答。咨询、打包、优化技能不触发业务测试。
- 默认平台 `https://qalab.claw.qihoo.net`、项目“纳米Work PC端”、任务“codex导入用例”。明确本地测试才切换对应平台，每条命令显式传 BaseUrl/base-url。不同平台不搬用 ID、会话或用例包。
- 首先查询真实项目和 `/api/verified-imports/capabilities`。默认使用 `import_mode: codex`，要求平台公布 `codex` 和 `qalab-codex-v1`。旧平台不支持时保留原包、说明需更新平台，不退回强制安装 Runner 或伪造通过。
- 使用当前 Codex 可用且获授权的浏览器、客户端或 CDP 工具操作真实应用。只检查实际需要的访问、登录与权限；不默认执行 Runner 预检。网页不依赖桌面 Runner；安装版客户端需要可用的控制工具，但不能把缺 Runner 等同于应用不可测试。
- 平台登录由用户在终端输入凭据。Windows 客户端使用 DPAPI；macOS 使用钥匙串及 Python 3.9+；本地离线协议校验使用 Node.js。这些辅助脚本不需要 Runner。A 电脑应用路径写入环境说明；B 的应用启动路径和设备参数由 B 的 Runner 配置，不能硬编码进平台步骤。

## 实测与形成可回归脚本

读取 [Codex 实测交付契约](references/codex-import.md) 和 [测试报告规范](references/test-report.md)。先建立完整场景清单，再逐条实际执行。执行过程中同步保存最终平台 DSL、观察结果、工具调用或日志/截图引用，不先随意点通再编造脚本。

- 根据真实 DOM 或当前平台注册表确定定位，遵守 [定位消歧](references/target-disambiguation.md)。不得以模糊同名、全局 contains XPath 或任意 nth 代替定位；不要删除同名元素来提高通过率。
- 前置导航、等待、清理测试状态和业务断言写进完整 script。环境/账号角色写 environment。纯备注不填 precondition，不依赖 A 电脑已打开的弹窗或已有会话。
- Codex 可以使用自己的工具执行；实际动作、目标、输入、等待和预期必须能映射到最终 DSL。坐标操作缺稳定定位、主观视觉判断缺可执行断言时继续补足；无法补足则明确不可回归，不称为已交付。
- 网络异常、延迟、顺序等场景参照 [网络场景](references/replayable-scenarios.md)。Codex 必须真实触发并记录模拟命中，最终脚本必须用平台支持的动作复现；不能仅模拟报告。
- `lint` 只检查协议，不执行应用。最终脚本若改变操作、目标或预期，需要重新实测受影响的完整流程；不能用旧日志证明新脚本通过。
- 通过必须实际执行完整脚本；业务失败保留完整可回归脚本，report 仅记录已执行到失败断言处的连续前缀，未执行后续步骤不得写成通过。失败断言记录 actual、expected、错误说明和证据，原样作为 fail 导入。
- 连接失败、定位不明、权限不足或工具不可用属于阻塞；未执行/不可转换场景保存在清单，不伪造业务失败，也不降级成无执行用例导入。环境/定位问题最多修复两次，保留原失败。

## 交付

用 `seal-codex.mjs` 封存已经记录的 Codex 观察包，再 `validate`、清单 `record --status tested`、`import`。通过和有证据的业务失败均可提交；技能不会生成成功证据，也不借助双次 Runner 实测作为导入门槛。报告引用和指纹仅用于追溯及一致性检查，不是平台独立认证。

平台记录“Codex 实测通过/失败”，保存可回归脚本与首次结果，不绑定生成设备、不冒充平台 Runner 已验证。B 电脑在平台选择拥有权限的执行设备，执行库中脚本并生成新的回归记录。B 的账号仍需项目与设备权限。

用户明确要求 Runner 双次复验且具备环境时，可选 [原 Runner 工作流](references/workflow.md) 与 [原验证接口](references/platform.md)；它不替代默认 Codex 执行，不是技能使用条件。

回填始终带清单，完整列出实测通过、实测业务失败、阻塞和未交付场景及原因。有效 accepted 回执后登记，完成本地测试报告再结束；不轮询去重、不创建监控，不把“已提交，后台整理中”说成已入库。网络重传保留 external_id 和原包，最多两次。

**每次通过本技能进行测试，必须交付独立的 `report.html` 测试报告，并在最终回复提供可点击的绝对路径。** 按 [测试报告规范](references/test-report.md) 编写可离线预览的单文件报告，覆盖全部计划场景、真实结果、缺陷证据及逐条导入状态。全部通过、发现业务失败、全部阻塞、部分完成或无法登录/导入时均适用；不能只给聊天总结、清单 JSON 或平台链接。等待用户补充条件时先保存阶段报告，继续执行后更新同一报告并保留原始证据。纯咨询、优化或打包技能不触发业务测试报告。

用户请求授权范围内的测试与结果回填；付费、公开发布、删除业务数据等额外动作需另行授权。不隐式提交 Git 或部署。
