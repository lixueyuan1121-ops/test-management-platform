# AI Native 质量评测

样本覆盖需求理解与场景、独立用例审查、执行证据核验三个阶段。调用与生产使用同一提示词、输出校验和引用检查，保存每项结果、提示词哈希、数据集哈希、耗时、模型报告的实际费用及输出 token。

- `synthetic`：完全合成的已知约束，验证明确的专项能力。
- `draft`：真实需求改编的待校准候选样本，不是产品确认的标准答案。默认不向模型发送，不计入正式准确率。私有样本使用本地数据集，不随公开仓库分发。
- `reviewed`：由产品／测试负责人复核输入与预期后填写确认人，才可用于产品口径的回归统计。目前没有这一类样本。

需求理解样本的自动评分只检查验收编号的场景覆盖及人工确认标记；具体业务含义按每条 `rubric` 人工核对，报告明确标记 `needs_semantic_review`。不得把结构检查通过当作正确理解需求。

在 `backend` 目录执行：

```bash
# 离线检查全部样本结构，不调用模型
.venv/bin/python -m scripts.eval_ai_native

# 默认仅运行合成和已人工标注样本；不读写业务数据库，不调用执行机
.venv/bin/python -m scripts.eval_ai_native --run --provider claude --output /tmp/ai-native-eval.json

# 固定样本与历史报告比较；样本内容相同才对比标签匹配结果
.venv/bin/python -m scripts.eval_ai_native --run --sample evidence-conflict --output /tmp/ai-native-eval-next.json --compare /tmp/ai-native-eval.json
```

公开默认数据集只含 8 个合成样本。如要评测待校准的真实需求摘录，需在明确授权发送给所选模型服务后，通过 `--dataset` 指定本地数据集并使用 `--include-draft`。私有输入和输出放在被 Git 忽略的 `reports/*-private*.json` 中。不要把 API 凭据、完整执行环境或真实用户数据加入评测文件。

真实需求试点的样本与报告保留本地，未随代码公开提交。通用的[流程调整说明](../../../docs/ai-native-quality-loop.md)记录质量检查环节及局限。

后续调用除哈希外会保存提示词与原始响应（最多 200,000 字符并标记截断），以便复核无效 JSON；原始输出保留不放宽生产解析。早期报告未保存的原始输出不回填。

本次真实模型试验首先发现原正例仅有“保留”值而没有对象标识，模型判证据不足。随后补齐正例的目标文件与字段，并保留 `evidence-unidentified-target` 反例。样本版本变化由哈希保留；不得把修改样本后通过解释为模型质量提升。

后续标注应同时检查正确接受和正确拒绝，保留模型误判及人工修改原因。仅有有限合成样本不能推导线上误判率或作为自动发布依据。

本轮记录：`reports/2026-09-13-synthetic.json` 是最后一次完整合成运行（7 项匹配、1 项 180 秒超时），配套输入及哈希保存在同目录。`2026-09-13-calibration.json` 保留此前的校准输出，包含分类协议错误；不合并不同轮次来宣称全部通过。初次报告只有 provider，未固定或捕获实际模型版本；后续报告会记录配置，模型配置为空时需注意默认模型可能变化。
