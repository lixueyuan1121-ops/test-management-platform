# 任务日报 skill 接入

用户安装包独立上传到服务器，不进入 Git。默认安装目录为 backend/.skills/tuitui-daily-report；可通过 TASK_DAILY_REPORT_SKILL_DIR 指定其他完整目录。

安装（在仓库根目录执行，升级时追加 --upgrade）：

```sh
backend/.venv/bin/python backend/scripts/install_task_daily_report_skill.py /path/to/tuitui-daily-report-skill-latest.zip --sha256 <安装包校验值>
```

安装器保留原始脚本副本和全部参考文件，增加平台 JSON stdin 入口。已有推推命令行入口保持兼容。相同包重复安装幂等；升级先保留旧目录备份，不同原包拒绝覆盖。版本 9 校验脚本、SKILL.md、原 HTML 模板和平台样式文件哈希。

编写日报接口校验项目权限和任务归属后，保存筛选任务的功能/需求（title）、条目映射 ID，以及仅用于本地标题的项目名（product_name）、仅用于本地排版的规划版本（target_version）与状态快照，交给现有 AI 队列。模型总结与审校仍只接收 title 和 ID；负责人、优先级、风险、进度等其他列不进入模型或正文。安装后的 skill 通过 --summary-prompt-json 读取原内容提炼规则，保留全部条目；平台现有 AI 服务先润色，再仅对照 title 同时审校事实和表达质量，保留通用术语解释与直接用途，避免把要求写成已完成或把建议当作已有安排。明确功能不允许空说明或标题同义复述；发现质量退步自动修订一次，仍不合格则明确报错。skill 通过 --validate-summary-json 校验任务 ID 和完整覆盖，过滤额外模型字段，再通过 --tasks-json 生成正文。

正文先按规划版本分组，再按用户确认的“测试完成 → 已上线 → 测试中 → 回归中 → 待开发修复 → 阻塞 → 有风险 → 待跟进 → 待分配 → 暂停 → 已关闭”排序；同状态保留筛选顺序。数字版本按新到旧展示，其他具名版本保留首次出现顺序，未填写版本单独放最后。只依据本次筛选范围的快照决定样式：明确版本且所选任务全为测试完成/已上线时，生成“版本更新说明”，采用参考页的渐变页头与更新条目，版本整体状态显示在页头，不在每条更新项旁重复状态小标签；含测试中或其他未完成/未知状态时生成“测试日报”，按状态分节。无版本条目也采用测试日报，不据此推断发版。

每项保留 AI 润色后的加粗标题、有依据的具体类型标签（包括安全修复、能力打通等）与“改动 + 用途”说明；原有 a/b/c 子项按原序展开。只有原文明确提及的其他需求、遗留问题或主要问题才单独成节，问题加警示标识；小结保留真实状态、重点及待跟进项，不引入其他字段或编造发布结论。版本与状态由程序填入，不交给模型改写。多版本各组用本组功能标题和已审校内容生成一句主题导语，单条目组不重复导语；状态与数量由本地快照统计。多版本不再逐组复述功能小结，仅有其他需求或问题时保留简短索引提示；单版本保留状态说明与不重复的语义小结。这些归纳调用仍不接收版本、状态等列。Markdown、文本及 HTML 保持相同层级和顺序，正文可继续手工编辑。旧队列若缺少版本/状态，则显示未填写规划版本/状态未记录；历史日报和已发布快照不变。多任务分批总结后统一归纳，失败明确报错，不回退到字段拼接。生成不拉取群消息、不发送消息。

生成输入和结果使用独立 task_digest_generation 表的 LONGTEXT 字段，避免 AI 队列 TEXT 长度限制；仅生成者且仍有项目写权限可读取结果。前端显示排队和总结阶段，完成后可继续编辑、保存和导出 Markdown/文本。

发布 HTML 时通过 --html-json 调用同一 skill，采用用户指定参考网页 https://pcvgfvzrg.zhaomi.cn/ 的卡片与编号版式，并按最新 prompt 使用浅色渐变页头、白色卡片、编号行与缩进说明。样式来自随适配器安装的 references/platform.css；原 references/template.html 保留。功能概览放入页头，标题默认以平台项目名开头，手工修改标题保持原样；单版本仅显示一个页头，不依赖标题文字是否相同，多版本增加可跳转的版本总览表和返回总览入口，正文使用紧凑标题栏；页头明确本次筛选数量、归属组数量和状态适用范围，不推断整个版本完成或上线。历史和人工编辑内容保持原样，分项状态数量缺失或与正文不符时不编造数量；版本更新说明使用浅蓝紫色，测试日报使用浅青蓝色及状态小节，发布说明采用淡黄色提示块。生成后校验 HTML 标签闭合、style 位置及 head/body 顺序。HTML 对内容先转义再支持安全加粗及链接，支持窄屏换行。HTML 快照存储在 task_digest_publication 表。日报与测评报告共同调用 report_publishing.publish_html，复用已有 Nami 部署服务、配置和凭据；链接保存在 task_digest_deployment 表。服务不可用时回退到平台 /d/<code> 短链，此读取接口仍要求登录和项目查看权限。Nami 链接沿用现有分享方式，持有链接可查看。日报发布通过同一服务主动请求 Nami 短链，不改全局配置；测评报告仍沿用原 NAMI_SHORTLINK_ENABLED 配置。短链服务不可用时保留可访问的原链接并提示。

发布自动保存正文，同一快照的成功 Nami 链接直接复用；编辑后发布产生新链接，旧链接仍展示原快照。已有日报及已删除任务的历史快照继续兼容。skill 子进程只接收 JSON，不继承数据库或机器人凭据。

代码发布仍执行原来的 bash scripts/update.sh；该脚本没有修改。发布后执行上述私有安装命令并追加 --upgrade。

验证：在 backend 目录执行 .venv/bin/python -m unittest scripts.test_task_daily_report_skill scripts.test_task_ledger scripts.test_report_publishing。设置 TASK_DAILY_REPORT_SKILL_ARCHIVE=/path/to/package.zip 可使用真实安装包验证；无该变量时使用最小接口夹具，CI 不依赖私有包。测试替代 AI 和在线发布调用，实际模型与部署结果另在平台页面验证。
